# Bible: player text (desc, change notes, status popups, glossary)

Part of the Bible rulebook (core rules: [12t_projects/bible/CLAUDE.md](../../../12t_projects/bible/CLAUDE.md)).

## Authored text, status keywords and desc style
* **`.sk-hero-desc`** (description box right of the hero icon/title): `flex:1; min-width:0; margin-left:14px`; gold accent bar (`background:var(--panel); border:1px solid var(--line); border-left:3px solid var(--gold); border-radius:4px; box-shadow:0 1px 3px rgba(0,0,0,.3)`); font **Prompt** 12px / 1.42, `var(--muted)`; no height limit; full width under the title on mobile; **no native `title` tooltip**.
* **Authored-text markup** (card `desc`, support results, server `changeNote`, glossary text). All of it renders through one function, `renderRichText(str, skill, lck)` = `renderStatusKeywords(formatDescTokens(...))`; any new text surface calls it. The styles (`.sk-val`, `.sk-val-red`/`.sk-tip-red`, `.sk-desc-skill-link`, `.sk-mech-link`, `.sk-status` + popup) are global, never per-container.
  * `**value**` → gold bold (`.sk-val`); a skill name inside `**…**` becomes a link (see bible-desc-writing, "Interactive Skill Cross-Linking").
  * `__value__` → oxblood bold (`.sk-val-red`, `var(--seal)`) for downsides/warnings.
  * `<span class='sk-protip'><b>Pro Tip:</b> …</span>` → a green line (`--pro`) of practical advice inside a desc, on its own `<br>` line after the base text (user 2026-10-09, first use: Wolf Continuous Blade). For how-to-play advice only, never for a limit (`__…__` red) or a code anomaly (the bug / unintended chips).
  * `[statusName]` / `[statusName3]` → purple hoverable status (trailing digits are literal text).
  * `^^term^^` → teal glossary link (see Mechanic glossary below).
  * `{{credit:id}}` → a small gold **scroll** button (`.sk-credit`) that opens the co-author pop-up (ผู้ช่วยเรียบเรียงคัมภีร์ไบเบิ้ล) open on that `CONTRIBUTORS` entry's page. **Convention (user 2026-10-06):** when a finding came from a fan, put the token right after the text of that finding **everywhere it appears** (the `desc`, `bbBug`, `tooltipNote`, `liveCheck` or `BB_ISSUES_EXTRA` text; the BB issues page renders the same strings, so it gets the scroll too), and add the fan to `CONTRIBUTORS` with a Thai explanation. `[CREDIT ERROR]` fails a token with no entry.
  * Stat names may use `<span class='dmg-agi'>AGI</span>` (`.dmg-tal/atk/def/agi/vit/int/cha/lck`).
  * Server `changeNote` bullets start with a tag that `formatServerNote()` turns into a chip: `[Buff]` green, `[Nerf]` red, `[Adjust]` / `[Rework]` blue, `[Fix]` violet (a server bug fix, e.g. ToT Chameleon crit gear). Bullets are separated by `\n`, not `<br>`.
* **Status keywords (`STATUS_CLASS_MAP`, `STATUS_DESC_MAP`, declared just before `const SKILLS`):**
  * `STATUS_CLASS_MAP` is the single source for a status's classification string (e.g. `"Debuff, Magical, Lock"`). Add an entry only after checking `StatusData.cs`'s `is*Status` functions **and** the generic per-status switch in `CharacterControl.cs` (bible-skill-research, Dead Code Verification Gate item 4). An unmapped name renders as plain bracket text (= still needs research).
  * `STATUS_DESC_MAP` gives the optional 2nd popup line: a string, or `(sLv) => string` for level-scaled effects (`getStatusDesc(name, sLv)` passes `null` for `[name]` with no digits → formula in words; a number → computed value). Verify values at the **apply site**, not the `removeStatus()` mirror.
  * **Per-server popup text:** `STATUS_DESC_SERVER[server][name]` replaces the `STATUS_DESC_MAP` entry on that server (`getStatusDesc(name, sLv, lck, server)`, server defaults to the skill page's `currentServer`). Used for ToT `holywolf`.
  * **No repetition:** a fact goes in either the status popup or the card `desc`, never both. What the status does → `STATUS_DESC_MAP`; the card names it (`[ashura${rank}]`) and says only what the skill adds.
  * Status mentions inside `STATUS_DESC_MAP` link to other statuses; cycles stop at the repeated name. Popup is a real nested `<span class="sk-status-tip">` built by `renderStatusTip(cls, desc)` (shared by `[name]` and the `status:{}` badge). CSS gotchas: `white-space:pre-line` on the absolute popup needs `width:max-content`; the divider span needs `display:block`; `text-wrap:balance` on `.sk-status-tip` evens its lines so a popup that wraps by one short word has no near-empty last row (user 2026-10-26, Stasis Blow [paralysis]).
  * **Auto-badge vs inline:** a card's `status:{name, sLv, class}` auto-prepends a badge (`sLv` may be a per-rank function). Any `[name]` of that status in the `desc` (name-only, case-insensitive) suppresses the auto-badge entirely; a card showing two levels places both inline. Use bare `[name]`, never hand-written `<span class="sk-status">` (the renderer skips pre-wrapped spans as a fallback).
* **Reach moves to the `reach` field (2026-10-13, user; Panda first, then class by class):** a card that has a `reach` field never states a size in its `desc` (no `รัศมี **N m**`, `ทรงกลมรัศมี`, `กว้าง **`); the range badge and its 3D popup show it, and `[REACH DESC ERROR]` fails a card that does both. A modifier line may still say in words that a skill changes the size when the number lives in `reach`. **No hit-shape lines either (user 2026-10-26):** a card with a `reach` (a field or one attached at runtime) does not describe the shape of its hit boxes ("ท่า 1: ฟันเป็นรูปกรวยด้านหน้า", "ครั้งที่ 2: เริ่มห่างจากตัวไปด้านหน้า"): the range preview draws them. A line that also states a count, a KO, a chance or a cooldown keeps those facts. Cards of classes not yet migrated keep following the rule below until their class is done (`[REACH BACKLOG]` counts them).
* **Every `desc` states its reach (verified from source), for cards with no `reach` field yet:** a circle (`FindAreaTarget`, a `sqrMagnitude` radius, `findFriends`/`findEnemies`) is `รัศมี **Nm**` with its centre (รอบตัว / รอบเป้าหมาย); **every radius is 3D (2026-10-07, user):** a `FindAreaTarget` circle adds its height `สูง **Hm**` (the `TargetHeight` argument), a flat `findEnemies` / `findFriends` / `findClosestEnemy` range adds `(ไม่จำกัดความสูง)`, a full-3D distance check or a `SphereCollider` trigger is `ทรงกลมรัศมี **Nm**` ([12Tails-Mechanics-Reference.md](../../../12t_reference/12Tails-Mechanics-Reference.md) §4); a modifier line that only changes a radius may leave the height to the base skill line; a straight-line distance (cast or target range, raycast length, travel) is `ระยะ **Nm**`; a box is `กว้าง / ยาว / สูง` (full width); a cone or fan gives its angle. Target-mode skills with no gate of their own say `ระยะ **40m**` (the target lock, [12Tails-Mechanics-Reference.md](../../../12t_reference/12Tails-Mechanics-Reference.md)); self skills say ตัวเอง; skills with no distance check say `ไม่จำกัดระยะ`. A passive that only changes another skill names that skill (its card carries the geometry). When the size lives only in a prefab or animation, say so instead of guessing. A size the code multiplies by the caster's `rangeMod` is written `N×rangeMod m` (a lifetime `N×rangeMod วินาที`, a reach from speed × lifetime too); a plain-number size stays `Nm`, and one box may mix both ([12Tails-Mechanics-Reference.md](../../../12t_reference/12Tails-Mechanics-Reference.md), `rangeMod`).
* **Line wrapping (2026-10-06, user):** no desc paragraph may end on a one-word last line at the desktop view (the full-width box since the head strip of 2026-10-26, about 800 px). **Orphan guard (2026-10-26 sweep):** Chrome's `text-wrap:pretty` does not see Thai words (127 paragraphs ended on one word), so after every hero render `glueDescTails()` glues the last 8+ letters of each desc line (`.sk-desc-line`, an icon line's text) into a nowrap `.sk-desc-tail`: cut at the space nearest the end when the tail stays within 20 letters (Thai separates phrases with spaces; a word cut alone split เป้า|หมาย), else at a word start (`Intl.Segmenter('th')`); a plain wrapper that ends the line (a red limit, a Pro Tip) is entered, a status or link is not; tails over 30 letters and lines under 16 letters are left alone. DOM only, so the validator and the delta keys see no change. The 2026-10-26 scan found no one-word last line on any card or server at 1920 × 1080. `.sk-hero-desc` still has `text-wrap:pretty`; a `**value**` of ≤ 20 visible characters gets `sk-nobr` automatically (so `+5 / +10 / +15%` or `DEF ÷ 3 + 10` never splits); `glueThaiLoanwords()` (`NOBR_THAI`) keeps loanwords Chrome's Thai breaker splits (ดาเมจ, คูลดาวน์) whole. When a new desc still ends short, first trim words without changing a number; if that only moves the problem, wrap the closing phrase in `<span class='sk-nobr'>…</span>` (single quotes work in both string styles). Check with a scan of every card's last line per `<br>` paragraph (Range rects per character), desktop 1920×1080 and phone 390 px for overflow.
* **Omit from `desc`:** wrapped durations (`chaAdjust`) and wrapped proc chances (`lckAdjust`); chips show them. The start-of-mission cooldown too (user 2026-10-26): it is the cooldown chip's `· ติด CD เริ่มฉาก` note or a `คูลดาวน์เริ่มฉาก` chip (bible-card-fields), and no text names the game modes it applies in; `[CD START ERROR]`. Also the standard on-hit **+1 SP** (unusual SP gains may be mentioned).
* **`desc` house style (Thai, adopted 2026-10-03).** A player who never read the code must be able to tell what happens, to whom, how often and for how long.
  * **Order:** base line = [เงื่อนไข/ตัวกระตุ้น] → การกระทำ → เป้าหมาย + reach → ผล + ตัวเลข → ความถี่/ระยะเวลา. Then `<br>• ` bullets for extra rules of the base effect, then one `<br>**Skill:** …` line per modifier skill, then `<br>__…__` downsides/limits last.
  * **Every effect says how often it happens:** `ครั้งเดียว` (once per cast/per death/per target), `ต่อฮิต`, `ทุก **N วินาที**` (a tick or periodic check), `ทุกครั้งที่ …` (an event trigger). When a periodic check grants a buff and also does something one-off, give each its own sentence or bullet (Last Hope: the buff is re-granted every check, the heal is once per death).
  * **A duration says what it is the duration of:** a flat duration written in the desc is attached to its status or effect (`[lastHope] นาน **12 วินาที**`). When the card has a Duration chip, the desc must make clear which effect the chip times (normally the status named in the base line). Wrapped durations stay out of the text (rule above).
  * **Who:** ตัวเอง (the caster; never ตนเอง, and use the class animal name only to contrast with a summon or a target, e.g. Phoenix vs ลิง), เพื่อนร่วมทีม (first mention; `เพื่อน` after), ศัตรู, เป้าหมาย (the selected target). Say `รวมตัวเอง` / `ไม่รวมตัวเอง` when allies are affected, and give caps: `สูงสุด **N** ตัว`, `สูงสุด **+N**`, `ซ้อนได้สูงสุด **N** ครั้ง`.
  * **Fixed terms:** วินาที (never วิ / sec / s), เลเวล (never Lv in prose; `[status3]` tokens are fine), ดาเมจ (not ความเสียหาย), ฮิต, ครั้ง, คูลดาวน์, ^^ดาเมจขาว^^ / ^^ดาเมจม่วง^^ via glossary links. Boxes are `กว้าง **N** ยาว **N** สูง **N**` (ยาว, not ลึก) and circles `รัศมี **N** รอบ…`.
  * **No code names in player text:** `talAdjust`, `lckAdjust`, `chaAdjust`, `getDebuff`, `sLv`, `hitMod`, variable names. Say it in words (`ดาเมจเพิ่มตามค่า TAL`, `โอกาสเพิ่มตามค่า LCK`, `เลเวลสกิล`). Allowed: `rangeMod` sizes (rule above), `^^term^^` glossary links, and formulas the card already shows in a chip.
  * **Markup:** numbers, percentages and timers in `**…**` (gold); skill names in `**…**` (they become links); statuses as `[name]` / `[name${rank}]`, never re-explaining what the status popup already says; `__…__` only for downsides and limits; modifier label `**Skill:**` (colon inside the bold, the link resolver strips it). **Spacing (2026-10-07, user; `^^…^^` glossary links too, 2026-10-16):** a `**…**`, `__…__` or `^^…^^` token never touches a letter or digit (`ระหว่างนี้ ^^หลบการโจมตี^^ ได้ทั้งหมด`, not `ระหว่างนี้^^หลบการโจมตี^^ได้ทั้งหมด`; glossary links are checked in every text in the file, change notes and bug notes included): exactly one space between it and the word before / after (`รวมถึง **เพื่อนร่วมทีม** ได้`, not `รวมถึง**เพื่อนร่วมทีม**ได้`), even in Thai; punctuation (`(`, `)`, `,`, `:`, `;`) and `<br>` may touch it. Applies to card `desc` (all servers) and `STATUS_DESC_MAP` / `STATUS_DESC_SERVER` popup texts; `[BOLD SPACING ERROR]` checks both, rendered at every rank / dep rank / server and status level.
  * **Numbers never change in a rewrite.** Every claim comes from the class reference or `DecompiledSource/`; an unclear sentence stays as it is and goes on the open-questions list.
* **Change note = original → current, no history (user 2026-10-02):** a `servers.<srv>.changeNote` states the original (BB) value and the server's current value only: no earlier patches, hot fixes, dates or "raised then lowered" steps (never e.g. "(ลดเหลือ 4/8/12/16 แล้วเพิ่มใน Hot Fix 12/09)"). When several patches touched a skill, tag the net change from the original (Resistance 8/12/16/20 → 6/10/14/18 = `[Nerf]`). The history can go in `12t_reference/`.
* **Every balance change note gets a matching server `desc` (user 2026-10-25):** when a card gets a `servers.<srv>.changeNote` whose change shows in what the desc says (who it reaches, range, an effect, a limit, a status or stat value), add `servers.<srv>.desc` in the same edit, so the desc is right when that server's toggle is on. Only a change the chips already show (cost, cooldown, cast time, duration, damage formula) needs no desc copy. A server tooltip note that no longer applies is cleared in the same override (`tooltipNote: ""`, e.g. Reborn Clear Arrow). First set: the Reborn notes on Bless, Illuminate, Gospel, Blinding Light, Summon Soul, Clear Arrow, Mimic and Special Deal.
* **Server `desc` = base `desc` + the change only (2026-10-07, user):** a `servers.<srv>.desc` is the base desc copied word for word with only what that server `changeNote` changes edited in (a number swapped, a line added or removed). Never rewrite it from the patch note: every range, height, hit count, status token, skill link and `__…__` limit of the base stays. A removed effect simply loses its line (no "no longer" history text). A full rework (the note replaces what the skill does, e.g. ToT Mike Circle, Instant Blaze, Earth Guard) is the one exception. Check with a base vs server word diff at max rank.
* **Dependency-line `desc` format** (skills changed by `compatSkills` modifiers): one base sentence (with verified hit-box `ระยะ / กว้าง / สูง`, full width = `2×BaseWidth`, see [12Tails-Mechanics-Reference.md §4](../../../12t_reference/12Tails-Mechanics-Reference.md#4-hidden-mechanics--special-interactions)), then one `<br>` line per modifier `**<Skill>:** <what it changes>`, not repeating values a chip/toggle shows. Example:
  ```
  ชาร์จ **${rank+1} วินาที** แล้วปล่อยหมัดตรงไปข้างหน้า กว้าง **2m** ยาว **1m** สูง **2m** ทำดาเมจรุนแรงตามค่า ATK<br>**Delay Qi:** ค้างหมัดไว้แทนการปล่อยทันที แล้วปล่อยเมื่อกดโจมตีครั้งถัดไป<br>**Qi Burst:** หมัดยาวเป็นเส้นตรงระยะ **6m** (ปกติสั้นเพียง **1m**)<br>**Focused Art:** บวกดาเมจเพิ่มตามค่า SP ปัจจุบัน ณ ขณะโดนเป้าหมาย
  ```
  The modifier passive's card mirrors it: `ทำให้ **<Active Skill>** <what it changes>` (two actives: `ทำให้ **Pummel** และ **Tower Rush** ...`). Both link each other in `compatSkills` (bible-card-fields, "Compatible Skills Navigation").
* **Effect-line list (user 2026-10-26, variant 3 of the nAttack mocks; every run gets it since the same day, user: icons wherever they help):** on the skill page every run of `**Name:** effect` lines, a single line included, shows as a list, each line led by a **27 px** icon (`renderDescWithMods`; 18 px, then 36 px the same day, user: x4 the area, then "too big, try around 27px") **in the related-skills ring** (user 2026-10-26, `.sk-compat-ring`'s look: `<span class="sk-desc-mod-ico">` is a circle with the ink fill and a thin gold edge, the skill art zoomed 1.3x and centred on its visible pixels by `centreRingImg`; a gear sprite, `.is-gear`, is shown whole at 0.8x inside the ring). The line's text sits in one `.sk-desc-mod-t` inside a text box at least 27 px tall that centres it, so a 1-2 line item is centred on its icon and a longer one starts level with the icon's top (the span keeps the inline flow intact; a flex box straight on the text would split it). Two or more lines take two columns that fill down, as a grid over `--rows` rows so a row lines up across both columns (CSS columns did not); one line takes the full width; phones one column. The lines before the first run (or before the first `## topic`, or the whole desc when it has neither) are the lead (`.sk-desc-lead`), the skill's main description, in pure white `#fff` (user 2026-10-27; gold values, links, statuses, glossary terms and `__limits__` keep their own colours). **Every desc opens with a main sentence** (user 2026-10-27, `[DESC LEAD ERROR]`): a passive whose effects are all modifier lines still starts with one short line that sums them up in the mirror form `ทำให้ **<Skill>** และ **<Skill>** <what changes>` (Mine Lover, Far Reach), with no numbers the lines already give; the lines under it stay muted. The text after a run follows as its own block (`.sk-desc-after`) and topic bodies stay in the box's muted colour. A line counts when its label is a skill (`findSkillByMention`, its card icon) or a gear piece in `DESC_LINE_ICONS`; any other bold label, such as a condition, ends the run. A new gear line needs its `DESC_LINE_ICONS` entry, or it ends the run: `item_<cls>43` / `item_<cls>58` = the G. Marshal / G. Champion weapon, `item_rabEquip1` / `item_rabEquip2` = Marshal / Champion armor + helmet, `item_<cls>59` = the Lv 60 weapon (`comboGear`, `w59Dep`), `item_rbBelt` = the Reborn belts. Every line closes the spans it opens, or the whole desc renders as written. `[DESC LIST ERROR]` renders every desc at every rank, desc dep rank and server through `renderDescWithMods` and fails an icon line without an icon, a `DESC_LINE_ICONS` key missing from `assets.js`, or a lost alignment rule (the 27 px icon with its centring text box and `.sk-desc-mod-t`, the column-filling grid, `DESC_MOD_MIN = 1`). Measured 2026-10-26 at 27 px on all 1583 icon lines of 705 card variants (desktop 1920 × 1080 and phone 390 px): text centred on the icon (or level with its top for longer items) within 0.8 px on desktop and 1 px on phones, rows level across the two columns, no overflow. Against the 18 px icons, 56 tall cards fit the desktop screen at a 2-3% smaller page scale (at 36 px: 61 cards, 3-8%). Write the lines as before: one `**Name:** effect` line per modifier (the colon inside the bold, one space after), no new markup.
* **Desc shape for the full-width box (2026-10-26 sweep of every card, user: icons wherever they help):** lead (the base effect in the house order, about 250 characters at most) → `• ` bullets for extra rules → one contiguous run of icon lines → plain condition lines (`**PvP:**`, `**ลำดับการคำนวณดาเมจ:**`, never between two icon lines) → `__limits__` → Pro Tip. A skill or gear piece that changes this skill gets its own `**Exact Name:** effect` line (the exact card `name`, so it links and shows its icon) instead of a parenthesis or clause in the lead; a sub-detail of one modifier stays in its line; a skill named as part of the base action stays inline. A passive that changes two or more skills reads as a short lead plus one `**Skill:**` line per skill it changes (Knight of the Deep, Skill Bargain, Shadow Mastery). Gear lines read `**G. Marshal / G. Champion Wand:** (อาวุธ **+5% / +7%**, ชุด + หมวก **+7% / +11%**) …` with their `DESC_LINE_ICONS` entry. An icon line aims for about 65 visible Thai characters (it sits in a half-width column). When a base desc is reworded, every server desc built from it (`descSwap`, `ttoDesc` `.replace`, `chmRbLine`, an appended `d + "<br>**X:** …"`) gets its anchors updated in the same edit; an appended icon line goes into the run (`descSwap(d, "<br>__", "<br>**X:** …<br>__")`) rather than after the limits.
* **Topic groups for long, complex descs (user 2026-10-26, the left-rail look of two mocks):** a line `## <หัวข้อ>` starts a topic. The lines before the first topic are the lead; each topic shows its name in a narrow gold column at the left (`.sk-desc-topic-h`, 7.2em), its lines beside it, a hairline between topics; phones (≤ 620 px) stack the name above its lines. Inside a topic the lines render as usual (bullets, an icon run without its own top rule, limits, Pro Tip). **Every desc of about 500+ visible characters on any server gets topics (user 2026-10-26: every long and complex skill, the single-list ones included)**, and its base and every server show the same topics; a lone list becomes a topic of its own (`## ลำดับท่า` over a Zombie AI list, `## ผลต่อสกิล` over a passive's per-skill lines, `## สกิลเสริม`, `## อุปกรณ์`, `## การทำงาน`, `## ข้อจำกัด`, `## เคล็ดลับ`), and a topic may hold one line. Shorter descs may use topics when they read better. A desc that opens with a topic (no lead) has no rule above its first topic, and a support skill's cooldown note goes in its own `## คูลดาวน์` topic. Topic names are short Thai nouns that say what the group is about (เกราะน้ำแข็ง, ดาวตก, เตรียมจรวด, คูลดาวน์); every line keeps its content, only its place changes. A server desc built from a topic-grouped base adds its line to the right topic with **`descInTopic(d, "<หัวข้อ>", "<line>")`** (throws when the topic is gone, like `descSwap`); `chmRbLine` and `d + "<br>…"` would put it into the last topic or the limits.
* **Mechanic glossary (`^^term^^`, `MECHANIC_DESC_MAP`, `#mechanicModal`):**
  * The text between `^^` is the display text and the case-insensitive key, unless `MECH_LINK_ALIASES` maps it to `[key, stepIndex]` (Thai terms, sub-steps: `^^ดาเมจขาว^^`/`^^hit()^^` → `damagepipeline`; `^^ดาเมจม่วง^^`/`^^Effect Damage^^` → `effectdamage`; `^^hitMod^^` → `damagepipeline` step 4). Unmapped → plain text. Works inside status popups too.
  * Entry shape: `{title, steps:[{label, body, examples?:[{icon, name, caption}]}]}`. `body` goes through `renderMechCode` (`` `term` `` → `.mech-code` chip) then the normal markup. Examples use `SKILL_ICONS` keys and state the verified value (apply site, not `removeStatus()`); icons sit on the step's stage (116px desktop / 64px phone), no card box; an inline `{{examples}}` marker in a body is dropped (the icons always go on the stage).
  * **Layout "C · สปอตไลต์" (user 2026-10-19, picked from 3 mocks; replaced the 16:9 one-step slides):** `openMechanicPanel(null)` = the index (`renderMechanicIndex()`): one full-width row per topic (big title, the topic art peeking in from `renderMechTileBg()`, the step names, "N ขั้นตอน →"). `openMechanicPanel(key, stepIdx)` = one step (`renderMechSlide()`): named step tabs (only when a topic has 2+ steps), the step's example icons (or the topic art when it has none) on a stage at the left, eyebrow / title / body at the right, then ‹ ก่อนหน้า and ถัดไป: <next step's name> (the last step offers หัวข้อทั้งหมด).
