## Hub pages
* **Monster stats page (`mountMonsterStats`, TOOLS id `monster-stats`):** a searchable, race-filtered, column-sortable table of `MONSTER_STATS` (every `CharacterControl` decoded from the original client: Name, Type, race, Lv, max HP/MP/SP/KO, the 8 stats with `mag` shown as INT, weight, run speed, collider height (สูง) and radius (รัศมี) as `r[20]` / `r[21]` (null = —, method in the Mechanics reference §5.2), and whether the row is the Resources prefab or a map copy). Default sort is Lv ascending. English text uses Chakra Petch and numbers JetBrains Mono (both already loaded; Thai falls back to Prompt). Its own wide stage (`html.tool-monsters`, up to 1500px) and a window-height scroll box with a sticky header and name column. Data and method: [12Tails-Mechanics-Reference.md §5.2](../../../12t_reference/12Tails-Mechanics-Reference.md). Filter, sort and search are remembered in `localStorage` (`12t-bible-monsters`). Regenerate the data from the raw files, never edit rows by hand. `[MONSTER STATS ERROR]`.
* **Boss guide page (`mountBossGuide`, TOOLS id `boss-guide`, data `BOSS_GUIDE`, tile `badge: "Experimental"`):** a boss picker (tabs, ←/→ keys, remembered in `localStorage` `12t-bible-boss`, deep link `#boss-guide/<id>`) and one page per boss: hero (name, stats, immune list, flat armor, HP bar marking where each move starts being used), a to-scale top-down **range map** (`mapR` metres; each move's `zone` list of `circle`/`donut`/`rect`/`rays`/`arrow`/`mark`, forward = up, `at` = metres in front, `side` = metres to the side), the AI cycle and priority ladder (first matching rung wins; each `cycle` entry is `[name, maxSeconds, timeLabel, explanation]`: the bar width uses `maxSeconds`, the label shows the true length (a phase with an `rTimer` is shortened by `Random(0, rTimer)`, so `AI_idle(1, 1)` is "0–1 วินาที", an attack window is "สูงสุด N วินาที"), and a numbered step list under the bar explains what the boss does in each phase, user 2026-10-07) and the move cards (no strategy section: removed 2026-10-04 at the user’s request). Hovering, focusing or tapping a move card or ladder rung lights its zone (tap pins it). Each boss has its own accent (`.bg-page[data-boss]`, light and dark values); display text in Chakra Petch, Thai headings in Kanit, numbers in JetBrains Mono. "ดาเมจตั้งต้น" is computed from the boss stats (`atk × ATK + talAdjust(tal)` over the TAL + LCK roll, or a flat value); for `kind: "white"` moves (`hit()`) the top end also adds the boss's `dmgAdjust` roll `R ≤ ceil(0.2 × LCK) − 1`, while Effect Damage (`purple`) shows the exact value. It is the damage before the player's DEF. Boss move names are never bolded in the text (a bolded name would link to a player skill with the same name, e.g. Nightmare). Optional boss fields: `hpNote` (an extra hero line, e.g. Ewiniar's five parts sharing one HP pool), `mech` (`[{h, text}]`, a "กลไกของด่าน" section of mission mechanics that are not boss moves, e.g. Zera's crystal core explosion and Shade waves; added 2026-10-07), an empty `phases: []` (no HP-gated moves: the HP bar is hidden), move `kind: "move"` (movement-only moves, no damage, `cd: 0` shows as none) and `ship` (Ewiniar: a "กลไกบนเรือ" section with a to-scale top-down ship plan (bow up, data x already in screen space with the ship's right on the right), the cannon table, falloff tiles and expected damage computed from `ship.cannon`, and the armed-saw steps from `ship.saw`; hovering a cannon row or marker lights its trajectory and blast circle). Every value comes from [boss-reference.md](../../../12t_reference/boss-reference.md); add a boss there first.
* **Menu tile backdrops (TOOLS `art`):** every menu tile shows the original full-colour portrait(s) from `TOOL_ART`, faded (`.entry-art`, opacity `.22` light / `.2` dark, `.38` / `.34` on hover; hover only brightens, the art never moves) and feathered on its left edge so the title stays readable. `art` is a list of `"tool:<key>"` (`TOOL_ART`), `"skill:<cardId>"` (that card’s own icon from `SKILL_ICONS`, drawn square, tilted and fanned out by `--i`) or `CLASS_ART` names; phones show only the first. The grid is rendered four times side by side (`.entry-collage-track`, four `.entry-collage-block`s, so its right edge never scrolls into view) and slides left by exactly one block (810 px) in a 90 s linear infinite loop. The tile itself is 180 px tall (`.entry-wide .entry` min-height, 2026-10-04) (`@keyframes entry-collage-scroll`); it keeps scrolling under `prefers-reduced-motion: reduce` too (user request 2026-10-04). No scale or dice art exists in the ripped assets (checked 2026-10-04), so those two come from Openclipart (public domain CC0), picked for the game’s outlined cartoon look: server balance “Balanza” (openclipart.org/detail/131899), stat roll “Five Colored Dice” (/detail/174804). `TOOL_ART` holds 240 px WebP portraits with alpha from `RippedAssets/.../gamegui/story/characters` (class tiles use the class story portraits) and `icons/targetavatar` (the Golden King Bug avatar is an opaque square, so it gets a radial fade). Current picks: skill details the icon collage, server balance the scale, BB issues Cyborg Mole, monster stats the Stat Scan icon, boss guide Shadow Italus, CHA/AGI optimizer the Lunar Eclipse, Rapid Trance and Immunity icons, stat gain the Super Stat Plus icon, stat roll the dice, Golden King Bug map the Golden King Bug. Chameleon simulator: the Chameleon portrait (its old line-art `.entry-chm-art` mask is no longer rendered, 2026-10-04). A new tool adds an `art` entry.
* **BB issues page (`mountBbIssues`, TOOLS id `bb-issues`, tile `.entry-bug`):** groups every `bbBug`, every `tooltipNote` (all ranks), every red `__…คำอธิบาย…__` / `__…tooltip…__` line found in a desc at any rank, every `liveCheck` (tagged "รอยืนยันในเกม") and `BB_ISSUES_EXTRA` (issues with no single card) by class, with a filter (all / bugs / tooltips / **unintended behavior**). **Class filter (2026-10-09, user):** a second pill row (`.bbi-filter.bbi-cls`, gold when active, count per class, counts follow the type filter, falls back to all when the chosen class has none) narrows it by class; the server balance page (`mountServerChanges`) has the same row, counts per server. Both remember the pick in localStorage. **Unintended behavior (2026-10-08, user; kind `"unintended"`, card field `unintended`, gold `⚡ พฤติกรรมที่ไม่ตั้งใจ`):** the game does exactly what its code says, but nobody can have meant it (e.g. a resist is a zero-damage hit that rolls Auto Shield, `gobble` classed as a plain Buff so Dissolute strips it). Not a `bbBug` (the code is not misbehaving) and not a `tooltipNote` (the text is not wrong). An empty category says so. Entries only when the user asks and says which fact is credited to whom (first ones, 2026-10-08: Swallow, Gourmet Heart, Auto Shield). Rows open the card on the original server (`?server=og`). New notes appear there automatically; never hand-maintain a second list.

## CHA / AGI Optimizer tool (`cha-agi-optimizer`)

Tile "อยากสกิลวน ใช้แต้มน้อยสุดเท่าไหร่" (`mountChaAgiOptimizer`): per skill, the cheapest CHA + AGI for no downtime (cooldown ≤ duration). Each card = target CHA (with base duration) and target AGI (with base cooldown); no extra text lines (user decision).
* **Skills:** `CAO_SKILL_IDS` (Dark Edge, Lunar Eclipse, Rapid Trance, Immunity), values read from their `SKILLS` cards. Add only skills with a plain `agiAdjust(cd)` cooldown and plain `chaAdjust(dur)` duration. Perseverance applies to cards whose `dep` is `WOLF_PERSEVERANCE_DEP`. Controls: Revised Art toggle, shared Perseverance 0/1/2, per-card rank.
* **Custom card:** user types base duration (integer) and base cooldown (decimal); own Perseverance (`state.custom.persev`); recomputes per keystroke, updating only the result numbers.
* **Per-card override:** CHA/AGI numbers are editable (`.cao-big`); typing one solves the other (`caoMinAgi`, `caoMinCha` 0–512, "–" if impossible). `state.overrides[cardId|"custom"] = {stat, value}` via `caoPair()`; "↺ ค่าต่ำสุด" clears it.
* **Math:** `caoDuration = floor(dur×(1+0.015×clamp(CHA,1,512)))`, then Perseverance `floor((1.1+0.2n)×d)`; `caoCooldown = cd×128/(AGI+128)`, Revised Art `ceil(0.88×c)`. `caoOptimal` brute-forces CHA 0–512.
* **LCK and cycle chance (2026-10-06, user):** two shared inputs above the cards (`.cao-shared`): **LCK** (default 156, 0–999, `--stat-lck` colour, same `.cao-big` number style as CHA / AGI; caption shows the roll range `+0 … +ceil(0.2×LCK)−1`) and **โอกาสสกิลวน %** (default 100, 1–100). Every cast rolls `R` separately for `agiAdjust` (AGI + R) and `chaAdjust` (CHA + R); the chance is the share of the `m × m` roll pairs (`m = caoRollCount(lck)`) with cooldown ≤ duration (`caoCyclePairs`, one pointer walk). Cards show the cheapest pair reaching `caoNeedPairs(m, pct)`; **100% = both rolls 0 = the old LCK-0 result** (the LCK value changes nothing there). `caoOptimal` / `caoMinCha` / `caoPair` take `lck, pct` as trailing optional args (default 0 / 100). Both inputs are in the undo state; a blank field restores on blur. Not saved across visits.
* **Budget advice (not shown in UI):** uptime ∝ `(CHA+66.67)×(AGI+128)`, so keep CHA ~61 ahead of AGI until CHA hits target. "AGI first" was tested and is wrong.
* **Undo:** Ctrl+Z restores toggle/rank state (50 deep) only while visible (`root.hidden` guard). Text inputs: snapshot on focus, commit on blur/change; Ctrl+Z inside a field is the field's own.

## Skill Simulator tool (`skill-simulator`, 2026-10-12, user)

Tile **"Skill Simulator"** (English name by the user's choice) with a red chip **กำลังพัฒนา ห้ามใช้จริง** (TOOLS `badge` + `badgeRed: true` → `.entry-badge-red`; the same chip is the first line inside the page, `.rsim-wip`). Remove both only when the user says the tool is ready. `mountSkillSimulator`, **all 12 classes** (the class is picked through the shared **class gate** `openClassPickerModal`, as in Stat Gain / Stat Roll: it opens on the first visit and cannot be closed until a class is chosen, later the `.cls-picker-btn` at the start of the top row reopens it; picking another class starts an empty build and is undoable; modelled on Rain Niar's 2014 Rabbit SkillSimulator v3; user's screenshot is the layout reference).
* **Layout:** one top row: Level input, **แต้มปกติ** and **แต้มสาย C** (each one field, `remaining/max`, user 2026-10-12), Reset + Undo; then four tree columns (Basic, A, B, C: Sharp Shooter, Alchemist Doctor, Merchant, Magistrate for Rabbit) of 4-wide icon rows joined by an orange line, each column with a "ล้าง" button. **Deliberately not carried over (user):** hover tooltips (cells have an `aria-label` only), the per-class point counts, the image backdrop. Icons have no frame or box (user 2026-10-12). Learned = full colour with a gold glow, learnable = grey with a "+" at the icon's bottom-left corner: Basic / A / B are **green** (`--pro`) when one click reaches the skill by levelling only its own row and **red** (`--seal`) when the click also levels other rows (`skillSimMarker`); **Class C stays yellow** (`--gold`, single-click, shown only when the skill can be learned right now); no marker = the click does nothing (user 2026-10-12), otherwise darker grey; the dim states stay opaque (no `opacity`, the connector line must not show through). Wide stage `html.tool-rsim`. Runs in the hub's fit-one-screen mode (`tool-fit-screen`: the window never scrolls, `fitStageToScreen` scales it down to the viewport); under 900px it scrolls normally instead (2 columns, 1 under 560px).
* **Data:** `SKILL_SIM[class]` (four trees, cell `[iconKey, label, reqLv, reqPoints, [reqSkillIds]?]`, `0` = empty slot) is generated from `RabbitSkill.getSkill` + `getSkillTree` (decoder, plus the `rSkill` lines it does not print), never typed by hand. Icons reuse `SKILL_ICONS["rabbit_<file>"]`, so no new image data. Table and cross-check against the 2014 simulator: [rabbit-skill-reference.md](../../../12t_reference/rabbit-skill-reference.md) "Skill Tree Layout & Learn Requirements". All 12 classes share one layout (trees 2-4 are 30 / 30 / 20 cells, Basic is 15-18) and one rule set. A class is generated, never typed: `decode_skilldata.py` on `<Class>Skill.cs`, `getSkillTree` for the ids (Wolf writes it as `EqualityOperator(commandNum, N)`, the others as `commandNum == N` or `!= N`), the `rSkill` lines for Class C, tree names from the TailsTails site ("Glambler" fixed to Gambler), then the arrays go in `SKILL_SIM` and the name in `SKILL_SIM_NAMES` (the gate lists `CLASS_ORDER`). Shared skills (Stat Plus, Revised Skill / Magic / Art, Super Stat Plus) use the generic `SKILL_ICONS` keys (`statPlus1`, `revisedSkill`, ...); an icon that is missing is embedded from `RippedAssets/.../icons/skills/<class>/<file>.png` as `<class>_<file>` (58 were added for the 10 classes, about 400 KB). Each class's table and its 3-way check against the 2014 blog and TailsTailsSimulator live in `<class>-skill-reference.md`, section "Skill Tree Layout & Learn Requirements" (all 12 done 2026-10-12).
* **Rules:** [12Tails-Mechanics-Reference.md §3.6](../../../12t_reference/12Tails-Mechanics-Reference.md). `skillSimValid(cells, treeCount, set, lv)` checks a whole learned set (level, previous rank below 400, `rSkill`, points-before-it per tree, both pools); **One-click learning (the big difference from other simulators, user 2026-10-12):** **Not for Class C (user 2026-10-12): a Class C click learns only that skill, and only when its level, C points and required skills are already learned, so Class C is built one skill at a time; Basic, A and B keep the one-click rule below.** **No manual locks and no padlock / pin icons (user 2026-10-12, removed the same day):** auto-learn is free to pick any filler. clicking an unlearned skill runs `skillSimAutoLearn`, which also learns the earlier ranks, the `rSkill` prerequisites (recursively) and, per tree whose point requirement is short, the cheapest extra skills (fewest new skills first, so it reuses what is already learned, then top rows); it refuses (returns null) when a needed skill is above the level or a pool would overflow. "+" means that click would work. Nothing already learned is removed. Clicking a learned skill (`skillSimDrop`, user 2026-10-12): the clicked rank and every rank above it go (click rank 1 = unlearned, click rank 2 = back to rank 1); refused unless the set stays legal, so a rank cannot be unlearned under the next rank and a skill cannot be unlearned under a skill that needs it. "ล้าง" on a tree also drops C skills that needed it.
* **Servers (user 2026-10-12):** a **server gate** (`openSimServerGate`, the class gate's look, three buttons BB / ToT / TTO with their level cap) opens first on the first visit and then hands over to the class gate; neither can be closed until chosen.
