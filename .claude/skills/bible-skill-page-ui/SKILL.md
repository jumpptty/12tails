# Bible: skill details page UI and behaviour

Part of the Bible rulebook (core rules: [12t_projects/bible/CLAUDE.md](../../../12t_projects/bible/CLAUDE.md)).

## Phone layout
* **Phone layout (<900px, `html.tool-wide-hero`):** no `fitStageToScreen()` scaling; page scrolls; one column (search + card + related first, stats panels after via `order:1`); Test popup fixed at `top:26vh`; stat tooltips under the value (`positionStatTooltips()`); `.view` `animation-fill-mode:none` (its transform would break `position:fixed`). <560px: LCK-variance and Final chips full width; the preset swap pop-up table puts each label on its own line above the 4 numbers. At ≤900px the hero card shows round ‹ › buttons (`.sk-skill-nav`, `data-step` ±1) beside the skill icon that call `navigateSkill()`, the same as the ← / → keys; disabled at the first / last skill, hidden on desktop. **No unasked keyboard on touch screens (2026-10-05, user):** code never focuses a text field the user did not tap through plain `.focus()`; use `softFocus(el)` (top of the main script), which skips under `(pointer: coarse)` (tool open, class browser, PRESET window name field). Focusing buttons is fine.

## Delta motion and dependency strip
* **Delta motion (2026-10-05):** `renderHero()` is a wrapper: `heroSnapshot()` → `renderHeroNow()` (the real rebuild) → next frame `heroDelta()`. Changed `.sk-stat` / `.sk-dmg` chips, `.sk-cost-badge`s, desc `.sk-val`s and desc `[status]` keywords get `.sk-delta` (chips: one flash with the glow kept inside, a tinted fill + inset edge glow, no ring outside the chip, user 2026-10-05; desc text: gold flash); tooltip text counts as part of a field, so a tooltip-only change also triggers. A `button[data-dep-id]` whose rank, on-state or icon changed flips. Better (rank up, or on): `.sk-dep-flip-on` and a three-dot gold comet (`.sk-shot`, WAAPI arc) flies from the icon to every changed field, nearest first, pinging it on impact. Worse (rank down / off): each field flashes red (`.sk-delta-down`), a red comet (`.sk-shot.is-red`) flies from it back into the icon, and the icon's `.sk-dep-flip-off` is delayed so it turns grey as the last one lands. With no dep source, a **server switch** sends gold comets from the newly selected server button (`.sk-server-deps .sk-server-btn[data-server]`) to every changed field, pinging on impact; the server is compared with `serverSeen` (the value at the end of the last rebuild, because the buttons set `currentServer` before calling `renderHero()`), and while the server pop-up is open the whole comparison is held, so they fly when it closes. Otherwise, if exactly one stat input (player 8 + LV, enemy 8; `statInputs()`) changed, comets glow in that stat's `--stat-<key>` colour and fields ping with `.sk-delta-stat` (`--delta-c`); a higher player stat is "better" by default and a higher **enemy** stat "worse" (user 2026-10-05: enemy DEF up pulls the light in). Fires on every keystroke. Several stats at once (an enemy pick) go to the clicked-control branch below instead. Flicker lengths: ping 1.1 s, text 1.6 s. **Flashes survive rebuilds (user 2026-10-05):** `pingField` stamps `data-ping-cls` / `data-ping-at`; `renderHero()` notes every field still flashing (`pingCarryCapture`, same skill only), and after `renderHeroNow()` the field at the same place resumes with a negative `animation-delay` (`pingCarryApply`). A comet in flight resolves its target when it lands (`fieldPos` / `liveField`), so a fast second click on the same toggle cuts nothing off. **Colour (user 2026-10-05):** a field that did not get worse lights up (comet + ping `.sk-delta-stat`) in the typed stat's colour when exactly one stat input changed, otherwise in its own chip's stat colour (`statColorFor` / `CHIP_STATS` in `heroDelta`: cooldown AGI, or INT for Phoenix Fireball; cast INT; duration CHA / TAL; `sk-stat-lck*` LCK; damage chips ATK / TAL / DEF / ...; only stats `getUsedPlayerStatKeys` / `getUsedEnemyStatKeys` report for the skill, a stat whose input just changed first, so an enemy pick colours damage DEF). Gold only for fields with no stat (desc text, costs, odds chips). The summon stat block is not a field; each `.sk-summon-stat` row is (in the chip group, value from `.sk-summon-stat-value`, higher = better), so every changed summon stat gets its own comet in its own colour (HP = VIT colour, MAG = INT). Worse is always red, typing included. When any `.sk-dmg-formula` in a `.sk-dmg-row` changed, the row's changed chips are replaced by the row itself (formula + Raw + Final = one comet); on impact `pingField` flashes the row's chips together, each inside its own border, never the row block or the gaps between chips (the chips' solid backgrounds hide a flash on the row). Deps in `WORSE_WHEN_ON` (inside `heroDelta`: `wolfKatana`, `rabW59`, both ×0.75 weapons) count as worse when switched on (red comets in) and better when switched off; the flip class follows the button's real on-state: off → on `.sk-dep-flip-on`, on → off `.sk-dep-flip-off`, a rank change that stays on (or off) `.sk-dep-flip-swap` (turns over, no lighting change). The rebuilt button already has its new icon (max rank → off is the rank-1 picture), so `flipStart` puts the old `src` back and swaps it in when the flip is edge-on (`FLIP_MID`: 220 / 180 / 225 ms after the animation delay). The clicked dep button always flips, even when its icon and stored rank don't change (capture-phase click on `displayEl` → `depClicked`). While the server pop-up is open the comparison is held (`deltaHeld`) and `hideServerPopup()` plays it against the state before the first switch. `depClicked` / `deltaHeld` are `var` and the group selectors live inside `deltaFields()`, because `renderHero()` can run before those lines during mount. **Every other toggle shoots from its own control** (`deltaClick`, recorded by a capture-phase document click as a `[data-role]` / `[data-id]` selector because the rebuild replaces most controls; enemy picks map to the enemy icon): the skill rank icon (rank up = better, compared with `rankSeen`), Revised Art, the buff / debuff quick switches (`aria-checked`) and enemy picks. Better (on / up) = gold comets out with `.sk-delta` pings; worse = `.sk-delta-down` red flash and red comets into the control. Toggles inside the Buff / Debuff popup are held while it is open (`bd-backdrop` counts as a covering popup) and `bdClose()` (×, backdrop, Esc) plays them from that side's Buff / Debuff button, gold when that side ended with at least as many active entries (`bdCounts`, compared with `bdNSeen`), red when fewer. **Per-field direction (2026-10-05, all sources):** the source's better / worse is only a default. Each changed chip and cost badge compares the average of the numbers in its value part (average, not sum, so a range that collapses to one number, e.g. cooldown 34–38s → 11s at high AGI, still reads as lower) (`deltaValue`, snapshot `nums`) and goes by its own result for the player: higher is better, except cooldown, cast time (`LOWER_BETTER` on the chip label) and costs. A collapsed damage row takes its Final chip's direction (else Raw's). So a higher Combo rank sends the row's light inward in red (less damage) while the faster fire-rate number gets gold outward. Desc numbers, status keywords and the formula chip are unreadable and follow the source. All sources go through one `volley(c, srcUp, {tone, outDelay})`; it returns the last inward landing time, used for the worse dep icon's delayed flip. A change with no known source still just pings in a 30 ms cascade; switching skills plays nothing (the snapshot uses `idSeen`, the skill of the last rebuild, because `selectSkill()` sets `selected` before `renderHero()`). Fields are matched by order within each group, popups excluded. Plays under reduced motion too (user request, same as the Test floats). New value-bearing chips should use one of those classes to join in; keep the edit inside `renderHeroNow()`.
* **Chevron escalator (2026-10-06, user: style 2 of 5; the chevron rain and the edge level-up stack were tried and dropped):** besides its flash, every chip a comet reaches (`.sk-stat`, `.sk-dmg`, `.sk-summon-stat`; a collapsed damage row plays on each of its chips) gets one tiled chevron pattern (`.sk-esc`, an SVG tile per chip: chevron size 40% of the chip height clamped 14–40 px, stroke 20% of the size, half the dropped rain's) scrolling in the direction **the number itself moved** (`numDirOf`, user 2026-10-06: a shorter cooldown or cast time is better but scrolls **down**; a number that cannot be read, e.g. desc text, falls back to better = up), 1.1 s, opacity 0.45. Better / worse is shown by the colour only. **Colour = the light ball that reaches the chip** (user): the stat tone or gold going out (`col || SHOT_GOLD`), red coming back (`SHOT_RED`), the same values as the `.sk-shot` glow. **Chips only, never the stat inputs.** Hook: `escalatorOn()` in `volley` (on impact when better, with the red flash when worse). It sits at `z-index:-1` inside the chip (`isolation:isolate`), behind the text; a rebuild mid-scroll drops it (the flash carries over).
* **Dependency strip (`depSink` / `renderDepStrip`, spec `docs/superpowers/specs/2026-09-26-dep-strip-design.md`):** every dep button lives in one `.sk-dep-strip` under the description.
  * **Merged "rank 5" toggles (2026-10-05, user):** a Class C passive that sits on top of a 4-rank skill becomes that toggle's rank 5 (`iconFor` / `labelFor` show the passive at 5): Rabbit Hyper Shot + Snipe Mastery, Chameleon Fatal Strike + Extra Arrows and Critical Plus + Bulls Eye, Bison Brute Strength + Raw Strength. Formulas cap the base level at 4. When other code still gates on the old passive dep (Bison's `atkCoeffProc` / `lckProc` Raw Strength chance), that dep becomes a **view**: same `id` as the real toggle, `minRank: 4, maxRank: 5, defaultRank: 0` (on only at rank 5 under both gate styles: `> minRank` and `=== maxRank`) and `viewOf: <real dep>`. `depSinkAdd` draws no button for a view and moves its tag (e.g. CHANCE) onto the real toggle's strip item, holding it under `pending:<id>` if the view registers first.
  * Range exactly `0..1` → toggle; anything else → rank selector. `renderDmgToggle` on `0..N` jumps off ↔ max unless the dep sets `cycleRanks:true`.
  * Item = 40px icon (grayscale when off) + `label` + effect tags `CD CAST DUR CHANCE DMG HITS KO SHIELD STATS INFO`, coloured by stat. A dep used at several sites shows once with merged tags.
  * A rank dep may give `iconFor(rank)` / `labelFor(rank)` when its icon or label is not `<icon base><rank>` (Chameleon Piercing Venom / Deadly Venom, target poison level 0-6, crit bow). A duration/cd dep may give `addFor(rank)` for a non-linear addend (Increased Poison 0-3 / Deadly Venom: +2/4/6/10 s). Name a passive's dep id after its card (`increasedPoison` → `chameleon_increasedPoison`) so `[DEP BACKLOG]` resolves it.
  * **Order:** `renderDepStrip()` sorts skill toggles ascending by internal skill ID (`SKILL_INTERNAL_ID`, card id -> lowest `commandNum` of the family in `<Class>Skill.cs` `getSkillTree()`). A toggle is matched to a card by `<class>_<dep id>`, `common_<dep id>`, or its icon key without the rank digit. Gear, target-condition and mode toggles (`DEP_NOT_SKILL`, or no match, or the selected card itself) follow in insertion order. Each item carries `data-dep-order`; a new card needs a `SKILL_INTERNAL_ID` entry (`[DEP ORDER ERROR]`); a new condition toggle that borrows a skill icon goes in `DEP_NOT_SKILL`.
  * Add deps via `renderDmgToggle(dep, TAG)`, `renderDmgRankToggle(dep, TAG)`, `renderDepBlock(dep, rank, "", TAG)`, or `depSinkAdd(dep, TAG, html)`. Non-dep controls (SP/HP/weight/height inputs, Nine Steps rows) stay in the damage header. `[DEP STRIP ERROR]`.

## Class Badge in the Player Stat Panel

* `.sk-class-badge` opens the player panel: class portrait + name + the **PRESET n** button (`data-role="preset-open"`, replaced the caption "ค่าสถานะตัวละครของคุณ" 2026-10-05, user request). Portraits come from `CLASS_PORTRAITS` (96×96 colour PNGs from `minimal_class_icons/bg_removed/<Class>.png`), not `CLASS_ART` (the line-art backdrop). `updateClassBadge(cls)` is called from `renderHero()`; Common skills show the PRESET button only (no portrait or name); 40px portrait under `max-height:820px`. A new class needs a portrait (`[PORTRAIT ERROR]`). The Revised Art button sits at the badge's right end.
* **Enemy badge** (`.sk-class-badge.sk-enemy-badge`): its own red card above the enemy stats with preset icon, name, caption "ค่าสถานะตัวละครเป้าหมาย" and the immunities "i" button. Clicking the icon opens a 3-column `ENEMY_PRESETS` picker (closes on choice / outside click / Esc); choosing writes the values and clears "Custom". Hand-edits show "?" + "Custom". Ctrl+Z (outside text fields) undoes enemy changes, 20 deep (`selectEnemyPreset` / `undoEnemyChange`). Long names shrink via `fitEnemyName` (≥9/≥12/≥14 chars → 13/12/10.5px). Enemy panel is always visible; its stat grid keeps an empty first cell to align with the player's CHAR LV column.
* **Stat presets (2026-10-05):** the badge's **PRESET n : name** button (n = selected slot; just "PRESET n" while unnamed; long names end in "…", the badge is narrow) opens the PRESET window (`openPresetWindow`, `data-role="preset-win"` in a `.sk-server-backdrop`, up to 1120px): 5 cards side by side (phones: horizontal scroll), each with the class's story portrait in **game colour N on card N** (`CLASS_STORY_ART[cls]` = 5 × 320px WebP; colour 1 is `gamegui/story/characters/<Class>.png` as shipped; the game has colours 2-5 only as 75px face icons `gamegui/icons/heroes/<Class>1..5.png`, so colours 2-5 are that portrait recoloured with the icon-1 → icon-N colour mapping, user decision 2026-10-05, a one-off scratch script, not original art; colour 5 keeps the original skin although the game darkens it there (user decision: only fur / hair change; pixels unchanged in colours 2-4 are held fixed, and colour 5 learns the hair change only from pixels whose 8 neighbours also move, because blended hair/skin edges carried the darker skin onto Rabbit's forehead); Cat and Penguin used a wider match tolerance, and Penguin's colour shows only on the strip of head the portrait shows; empty, unselected cards are dimmed), a PRESET n tag, a green "ใช้งานอยู่" tag on the selected one, an editable **name** (24 chars) and **description** (160 chars) saved on every keystroke (`labels[i]`, kept apart from the slot data so an empty slot can be named), the 9 stats, the buff / debuff count, and a use button (ใช้ชุดนี้ / กำลังใช้อยู่ / เริ่มชุดนี้จากค่าปัจจุบัน; the portrait is a use button too). Using a card closes the window first (`presetUseSlot`). Esc / × / backdrop close it. The window title is `PRESET · <Thai class name>` (`CLASS_TH_NAMES`), with no subtitle. **Reorder:** drag a card's portrait (HTML5 drag and drop, `draggable` art button) onto another card; `presetMove` moves that preset's stats, buffs, name and description there and shifts the rest. Position is the number (leftmost = PRESET 1); the portrait colour moves with the preset (`colors[position]` = game colour 0-4, a permutation re-checked on load, default the game order, user request 2026-10-05); the preset in use stays selected wherever it lands; undoable with Ctrl+Z. A plain click on the portrait still uses the preset. **Reset to default** (header button `preset-reset`, red): asks in an in-window confirm (`presetConfirmReset`; Cancel focused, Esc / click outside cancel without closing the window), then `presetReset` clears this class only (5 empty slots, no names or descriptions, game colour order), puts the 9 stat fields back to their input `defaultValue` and turns everything off in the Buff / Debuff popups. Final (user decision): no Ctrl+Z, and the older preset undo steps are cleared so none of them can bring the data back. The card stat lists use the stat signature colours (`--sc:var(--stat-<key>)` on each label); the window and the change pop-up pin the bright dark-theme `--stat-*` values because they are dark in both themes. There is no slot bar any more (`[PANEL ERROR]` keeps it out). Each class has 5 slots, each holding the 9 player inputs (LV + 8 stats) **and the whole Buff / Debuff popup state** (`bd`: toggled stat buffs, damage / final-multiplier / hitMod mods, enemy stat debuffs, which custom entries are on, the popup's `bdServer` and both quick switches; custom entry definitions stay global). Not saved: enemy stats, Revised Art. Stored in `localStorage["12t-bible-stat-presets"]` = `{classes:{<Class>:{slots:[5 × {lv,atk,…,bd}|null], active, labels:[5 × {name, desc}], colors:[5 × 0-4]}}}`, re-validated on load (`presetLoadAll`; bad data = empty) and `bd` ids filtered against the live tables on apply (`presetBdApply`). **No save / clear buttons (user decision): autosave.** A real edit of a player input (`input` listener, `presetAutosave`) or a Buff / Debuff change (detected in `renderPresetBar` against `presetBdSeen`) writes into the class's selected slot (slot 1 until another is picked); loads, undo and skill switches never save, so viewing another class never fills its slots. Using an empty card = start a new set there from the current stats + buffs (no pop-up); a filled card = load it and open the swap pop-up. Selecting a skill of another class loads that class's selected preset with no pop-up (`presetOnSelect`, from `selectSkill`); Common skills use the last class. **Swap pop-up** (only when at least one chip of the open card changed; an identical preset or one that differs only in stats this skill ignores switches silently) (`showPresetPopup`, `data-role="preset-popup"` in a `.sk-server-backdrop`): changed stats as pills, then buff / debuff pills (`presetBdDiff`: `+` green = turned on, `−` red = turned off, popup server and quick switches), then every chip of the open card whose value text changed (`presetReadChips`: `.sk-stat-label` + each `.sk-stat-value`, formula excluded, Final digits read from `img[alt]`), before / after / flat / %, ranges per end and collapsed when both ends match (up to 880px wide; numbers in the damage formula's bold monospace face at 22px, 16px on phones; the "after" column bright gold `#f2cf6b` because the window is dark in both themes); green = better, red = worse, lower is better for cooldown and cast time. The delta flicker is held while it is open and plays on close (`hidePresetPopup`), like the server pop-up. Ctrl+Z undoes slot switches and new sets (`presetUndoStack`, 30 deep; stats and buffs together), sharing the key with the enemy undo, newest first (both stacks carry `at`). `[PANEL ERROR]` checks the PRESET button in the player badge, that the caption and slot bar stay removed, the storage key, and a `CLASS_STORY_ART` portrait for all 12 classes.
* **Stat grid keyboard (2026-10-05):** in both `.sk-stats-panel .sk-controls` grids (player 3 × 3; enemy 3 × 3 with an empty first cell) arrow keys move to the neighbouring field instead of stepping the number (no wrap at row ends; the empty enemy cell blocks), and a field selects its whole number on focus, by click or arrow (`select()` in a `setTimeout` so the click's caret does not undo it). The document-level ← / → skill switch ignores any focused `input` / `textarea` / `select` / contenteditable.
* Captions never wrap (`white-space:nowrap`; Thai has no spaces). `[PANEL ERROR]` guards the structure (no toggle, arrows or `.sk-controls-actions` row).

## Player Stat Input Highlighting (Stat Signature Accents)

1. `getUsedPlayerStatKeys(skill)` reads `cdWrapped`, `castWrapped`, `durWrapped`, `dmg`, `atkCoeff`, `defCoeff`, `lckProc`, deps.
2. `.sk-stat-glow-<key>` uses `--sg-color` for border/label/number and a static glow.
3. CHAR LV glows only when its controlling dep is on (`getDepRank(dep) === dep.maxRank`).
4. LCK glows only on a direct read (`lckProc`, literal `lckCoeff`, `lckAdjust()` in formula text), not for rolls inside `*Adjust`.
5. Summon sub-moves exclude player ATK/TAL/AGI per ownership flags (`ownStats`, `ownStatsDmgOnly`, `ownStatsKaiser`, `ownStatsPhoenix`, `phoenixFireballCd`).
6. **Summon stat feed** (`getSummonFeedPlayerStatKeys`): a player stat glows when its feeding dep is on **and** the fed summon stat is in `getUsedOwnStatKeys(skill)`. Feeds: Double Bot / Hidden Turret: CHAR LV → all; Synchro Mole: TAL → ATK/DEF; Phoenix Fire Soul: each stat → same (INT → MAG); Gadina Earth Soul: same 8-stat feed; Aegis of Earth: VIT → VIT. VIT also feeds MHP (`10×vit`). King Kaiser, Gaos, Ja and the Rabbit Contract mercenaries feed nothing. `[SUMMON FEED ERROR]`.

## Buff / Debuff Popup: Server Toggle & Quick Switches

1. **Popup server (`bdServer`: og/tot/tto):** own selector, independent of `currentServer`, session-only; decides which entries exist and their values.
2. **Per-entry server data:** `STAT_BUFFS` / `MOD_DEFS` entries may carry `servers:{tto:{...}, tot:{hidden:true}}` and/or `onlyServers:[...]`. `bdResolve(entry, server?)` returns the effective entry or `null`; the lists, `statBonus()`, `playerDamageModCalc()`, `enemyHitModCalc()`, `finalMultCountCalc()` all use it. Selections are kept by id across servers. Only verified values.
3. **Quick switches (`buffsSuspended` / `debuffsSuspended`):** suspend a whole side without clearing it; dims the button, popup shows `Off`; session-only.
4. **Character Hit Mod tool (`chm*`)** is separate: reads `MOD_DEFS` directly, has its own server toggle (`simState.server`, `#chmServerToggle`; `chmModOnServer()`; TTO opens `showChmServerPopup()` with `CHM_TTO_NOTE`). On TTO its inline `maxRAtk`/`maxRDef` rolls are 0 and the Poseidon HP Drain chance skips `chmLckAdjust`. **Its damage math does not use `tdlRoll`; mirror TTO changes by hand.**
5. **Final multipliers:** `STAT_BUFFS` `mult:{int:1.24}` = final multiplier after additive buffs (`floor((base+additive)×mult)`, epsilon-guarded), shown as `+N`. Uses: `recurrentNova5` (ToT only), TTO `honor4` (+50 CHA). **Final Multiplier section is ToT-only** (`finalMult1-3` `onlyServers:["tot"]`; custom `finalMult` via `finalMultOnServer()`; entries kept). Badges count only entries `bdResolve` keeps. `[FINAL MULT ERROR]`.
6. **Custom buffs/debuffs:** `+ Add` per section; `{id, kind, name, stat?, value}` in `localStorage["12t-bible-custom-bd"]` (ON/OFF is session state, new = ON). Kinds: `stat` (int ≥ 0, one stat or `all`, additive before `mult`), `dmgMod` ([-10,10]), `finalMult` (0–1000%, ToT only, one `ceil` step after the built-in 5% stacks), `hitMod` ([-10,10]), `enemyStat` (int, |N| ≤ 9999). Rules in `validateCustomBd()` (name required, ≤24 chars; storage re-validated on load). Names HTML-escaped.
7. **Enemy stat changes:** `enemyVal(el)` (typed value + net change, not floored; formulas clamp) replaces every direct enemy CHA/LCK/DEF read. Panel shows `+N = total` / red `-N = total` (`.sk-stat-bonus.neg`). `finalMultiplierAdjust(dmg, x)` takes a step count (CHM) or an array of percent steps.
8. **`ENEMY_STAT_DEBUFFS`** (same shape as `STAT_BUFFS`, `enemyStatBonus()`, toggles `bd-estat`): first entry `shame6` (Bat Shame Lv.6, -60 CHA).
