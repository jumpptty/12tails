# Bible: skill details page UI and behaviour

Part of the Bible rulebook (core rules: [12t_projects/bible/CLAUDE.md](../../../12t_projects/bible/CLAUDE.md)).

## Phone layout
* **Phone layout (<900px, `html.tool-wide-hero`):** no `fitStageToScreen()` scaling; page scrolls; one column (search + card + related first, stats panels after via `order:1`); Test popup fixed at `top:26vh`; stat tooltips under the value (`positionStatTooltips()`); `.view` `animation-fill-mode:none` (its transform would break `position:fixed`). <560px: LCK-variance and Final chips full width; the preset swap pop-up table puts each label on its own line above the 4 numbers. At ≤900px the hero card shows round ‹ › buttons (`.sk-skill-nav`, `data-step` ±1) beside the skill icon that call `navigateSkill()`, the same as the ← / → keys; disabled at the first / last skill, hidden on desktop. **No unasked keyboard on touch screens (2026-10-05, user):** code never focuses a text field the user did not tap through plain `.focus()`; use `softFocus(el)` (top of the main script), which skips under `(pointer: coarse)` (tool open, class browser, PRESET window name field). Focusing buttons is fine.

## Delta motion and dependency strip
* **Delta motion (2026-10-05):** `renderHero()` is a wrapper: `heroSnapshot()` → `renderHeroNow()` (the real rebuild) → next frame `heroDelta()`. Changed `.sk-stat` / `.sk-dmg` chips, `.sk-cost-badge`s, desc `.sk-val`s and desc `[status]` keywords get `.sk-delta` (chips: one flash with the glow kept inside, a tinted fill + inset edge glow, no ring outside the chip, user 2026-10-05; desc text: gold flash); tooltip text counts as part of a field, so a tooltip-only change also triggers. A `button[data-dep-id]` whose rank, on-state or icon changed flips. Better (rank up, or on): `.sk-dep-flip-on` and a three-dot gold comet (`.sk-shot`, WAAPI arc) flies from the icon to every changed field, nearest first, pinging it on impact. Worse (rank down / off): each field flashes red (`.sk-delta-down`), a red comet (`.sk-shot.is-red`) flies from it back into the icon, and the icon's `.sk-dep-flip-off` is delayed so it turns grey as the last one lands. With no dep source, a **server switch** sends gold comets from the newly selected server button (`.sk-server-deps .sk-server-btn[data-server]`) to every changed field, pinging on impact; the server is compared with `serverSeen` (the value at the end of the last rebuild, because the buttons set `currentServer` before calling `renderHero()`), and while the server pop-up is open the whole comparison is held, so they fly when it closes. Otherwise, if exactly one stat input (player 8 + LV, enemy 8; `statInputs()`) changed, comets glow in that stat's `--stat-<key>` colour and fields ping with `.sk-delta-stat` (`--delta-c`); a higher player stat is "better" by default and a higher **enemy** stat "worse" (user 2026-10-05: enemy DEF up pulls the light in). Fires on every keystroke. Several stats at once (an enemy pick) go to the clicked-control branch below instead. Flicker lengths: ping 1.1 s, text 1.6 s. **Flashes survive rebuilds (user 2026-10-05):** `pingField` stamps `data-ping-cls` / `data-ping-at`; `renderHero()` notes every field still flashing (`pingCarryCapture`, same skill only), and after `renderHeroNow()` the field at the same place resumes with a negative `animation-delay` (`pingCarryApply`). A comet in flight resolves its target when it lands (`fieldPos` / `liveField`), so a fast second click on the same toggle cuts nothing off. **Colour (user 2026-10-05):** a field that did not get worse lights up (comet + ping `.sk-delta-stat`) in the typed stat's colour when exactly one stat input changed, otherwise in its own chip's stat colour (`statColorFor` / `CHIP_STATS` in `heroDelta`: cooldown AGI, or INT for Phoenix Fireball; cast INT; duration CHA / TAL; `sk-stat-lck*` LCK; damage chips ATK / TAL / DEF / ...; only stats `getUsedPlayerStatKeys` / `getUsedEnemyStatKeys` report for the skill, a stat whose input just changed first, so an enemy pick colours damage DEF). Gold only for fields with no stat (desc text, costs, odds chips). The **KO badge** (`.sk-ko-badge`) is its own field (user 2026-10-06): the damage formula chip's text leaves it out (`deltaText` drops `.sk-ko-badge`), so a skill dep or input that only moves KO sends the light to the badge, not the whole formula / damage row; higher KO = better, gold (no stat), cost-badge flash style, value from `.sk-ko-value`. The summon stat block is not a field; each `.sk-summon-stat` row is (in the chip group, value from `.sk-summon-stat-value`, higher = better), so every changed summon stat gets its own comet in its own colour (HP = VIT colour, MAG = INT). Worse is always red, typing included. When any `.sk-dmg-formula` in a `.sk-dmg-row` changed, the row's changed chips are replaced by the row itself (formula + Raw + Final = one comet); on impact `pingField` flashes the row's chips together, each inside its own border, never the row block or the gaps between chips (the chips' solid backgrounds hide a flash on the row). Deps in `WORSE_WHEN_ON` (inside `heroDelta`: `wolfKatana`, `rabW59`, `catW59`, `mnkW59`, `pgnW59`, `batW59`, all ×0.75 weapons) count as worse when switched on (red comets in) and better when switched off; the flip class follows the button's real on-state: off → on `.sk-dep-flip-on`, on → off `.sk-dep-flip-off`, a rank change that stays on (or off) `.sk-dep-flip-swap`. Since 2026-10-07 (user) these are no longer flips: all three are the same 0.3 s scale pop (1 > 1.07 > 1); `-on` / `-off` also fade the colour in / out during it (no light slide: user dropped it, a masked sweep was not visible enough) (turns over, no lighting change). The rebuilt button already has its new icon (max rank → off is the rank-1 picture), so `flipStart` puts the old `src` back and swaps it in when the animation delay ends (`FLIP_MID` is 0 for all three). The clicked dep button always flips, even when its icon and stored rank don't change (capture-phase click on `displayEl` → `depClicked`). While the server pop-up is open the comparison is held (`deltaHeld`) and `hideServerPopup()` plays it against the state before the first switch. `depClicked` / `deltaHeld` are `var` and the group selectors live inside `deltaFields()`, because `renderHero()` can run before those lines during mount. **Rank and dependency toggles shoot from their rank pips, not the icon (2026-10-08, user; `pipPoint` in `heroDelta`):** rank up = the last lit pip (the one that just filled), rank down = the first pip that just emptied, where the red comets fly back in; the hero icon's `.sk-hero-pips` serves the skill rank, a dep's `.sk-dep-btncol .sk-pip` serves the dep, and a control with no pips falls back to the icon. **Every other toggle shoots from its own control** (`deltaClick`, recorded by a capture-phase document click as a `[data-role]` / `[data-id]` selector because the rebuild replaces most controls; enemy picks map to the enemy icon): the skill rank icon (rank up = better, compared with `rankSeen`), Revised Art, the buff / debuff quick switches (`aria-checked`) and enemy picks. Better (on / up) = gold comets out with `.sk-delta` pings; worse = `.sk-delta-down` red flash and red comets into the control. Toggles inside the Buff / Debuff popup are held while it is open (`bd-backdrop` counts as a covering popup) and `bdClose()` (×, backdrop, Esc) plays them from that side's Buff / Debuff button, gold when that side ended with at least as many active entries (`bdCounts`, compared with `bdNSeen`), red when fewer. **Per-field direction (2026-10-05, all sources):** the source's better / worse is only a default. Each changed chip and cost badge compares the average of the numbers in its value part (average, not sum, so a range that collapses to one number, e.g. cooldown 34–38s → 11s at high AGI, still reads as lower) (`deltaValue`, snapshot `nums`) and goes by its own result for the player: higher is better, except cooldown, cast time (`LOWER_BETTER` on the chip label) and costs. A collapsed damage row takes its Final chip's direction (else Raw's). So a higher Combo rank sends the row's light inward in red (less damage) while the faster fire-rate number gets gold outward. Desc numbers, status keywords and the formula chip are unreadable and follow the source. All sources go through one `volley(c, srcUp, {tone, outDelay})`; it returns the last inward landing time, used for the worse dep icon's delayed flip. A change with no known source still just pings in a 30 ms cascade; switching skills plays nothing (the snapshot uses `idSeen`, the skill of the last rebuild, because `selectSkill()` sets `selected` before `renderHero()`). Fields are matched by order within each group, popups excluded. Plays under reduced motion too (user request, same as the Test floats). New value-bearing chips should use one of those classes to join in; keep the edit inside `renderHeroNow()`.
* **Magic badge arrival (2026-10-07, user):** when a rebuild of the same skill newly shows the TTO `.sk-magic-badge` (server switch, a dep such as Synchro Mole for Auto Gyro Gun, anything that makes `isTtoMagic` true), `heroDelta` hides it (`.sk-magic-wait`, before the first paint, also while a pop-up holds the comparison), adds it as its own target after the damage-row collapse, and the volley fires an aqua (`--stat-tal`) light ball at it from the same source; on impact `revealMagic` pops it in (`.sk-magic-in`). `heroSnapshot` records `magic` (a visible badge); `deltaText` leaves the badge out of the Raw chip value. **Reverse on removal (2026-10-07, user):** when the badge goes away (back to OG / ToT, a dep turned off), `heroDelta` puts a ghost copy back in the Raw chip label row (`prev.magicHtml`, class `.sk-magic-out` at once so snapshots skip it); `magicOut` plays the pop-in backwards (shrink + fade, 0.5 s), removes it, then the aqua light flies from the badge back into the source (worse direction; the dep icon flip waits for it). **Badge list (2026-10-07, user):** the badge sits at the Raw chip label row right edge (row `flex:1`, badge `margin-left:auto`) and is a `<button data-role="magic-list">` with an aqua hover glow; a click (delegated on `displayEl`) opens `showMagicListPopup()`: the TTO server pop-up (`showServerPopup(selected, "tto", {bodyHtml})`) with 12 class tabs on top (`CLASS_PORTRAITS`, `CLASS_ORDER`, a count each; 6 per row on phones), one class shown at a time (opens on the current skill class), **two columns of rows, no scrolling (2026-10-08, user):** the pop-up is wider (`.sk-magic-popup`, 900 px), the big server logo is hidden on phones, and `fitMagic` switches to `is-compact` (26 px icons, one tab row) when the pop-up is still taller than the screen; names never truncate: a long one shrinks (14 → 10 px, the Thai line 11.5 → 9 px) and only wraps below that. One row per skill (40 px icon, name, Thai name, "เมื่อเปิด <dep label>" for `ttoMagicDep` cards) that opens that skill; the open skill is outlined gold.
* **Chevron escalator (2026-10-06, user: style 2 of 5; the chevron rain and the edge level-up stack were tried and dropped):** besides its flash, every chip a comet reaches (`.sk-stat`, `.sk-dmg`, `.sk-summon-stat`; a collapsed damage row plays on each of its chips) gets one tiled chevron pattern (`.sk-esc`, an SVG tile per chip: chevron size 40% of the chip height clamped 14–40 px, stroke 20% of the size, half the dropped rain's) scrolling in the direction **the number itself moved** (`numDirOf`, user 2026-10-06: a shorter cooldown or cast time is better but scrolls **down**; a number that cannot be read, e.g. desc text, falls back to better = up), 1.1 s, opacity 0.45. Better / worse is shown by the colour only. **Colour = the light ball that reaches the chip** (user): the stat tone or gold going out (`col || SHOT_GOLD`), red coming back (`SHOT_RED`), the same values as the `.sk-shot` glow. **Chips only, never the stat inputs.** Hook: `escalatorOn()` in `volley` (on impact when better, with the red flash when worse). It sits at `z-index:-1` inside the chip (`isolation:isolate`), behind the text; a rebuild mid-scroll drops it (the flash carries over).
* **Dependency strip (`depSink` / `renderDepStrip`, spec `docs/superpowers/specs/2026-09-26-dep-strip-design.md`):** every dep button lives in one `.sk-dep-strip` under the description.
  * **Merged "rank 5" toggles (2026-10-05, user):** a Class C passive that sits on top of a 4-rank skill becomes that toggle's rank 5 (`iconFor` / `labelFor` show the passive at 5): Rabbit Hyper Shot + Snipe Mastery, Chameleon Fatal Strike + Extra Arrows and Critical Plus + Bulls Eye, Bison Brute Strength + Raw Strength. Formulas cap the base level at 4. When other code still gates on the old passive dep (Bison's `atkCoeffProc` / `lckProc` Raw Strength chance), that dep becomes a **view**: same `id` as the real toggle, `minRank: 4, maxRank: 5, defaultRank: 0` (on only at rank 5 under both gate styles: `> minRank` and `=== maxRank`) and `viewOf: <real dep>`. `depSinkAdd` draws no button for a view and moves its tag (e.g. CHANCE) onto the real toggle's strip item, holding it under `pending:<id>` if the view registers first.
  * **Rank pips (2026-10-08, user):** every strip icon has one dot per rank under it (`depPipsHtml`, `maxRank - minRank` dots, cap 8; a plain toggle has one); filled gold = reached. A pip that just filled pops with a soft glow (`.pip-in`), one that just emptied fades to hollow (`.pip-out`); `depPipSeen` (per skill + dep) means a rebuild or skill switch plays nothing. **The hero skill icon** of a `maxRank > 1` card has the same pips (`pipsHtml`, `.sk-hero-pips`, hung under the icon with `position:absolute` so the header does not grow): one per rank, rank 1 always lit because a skill has no off.
  * Range exactly `0..1` → toggle; anything else → rank selector. `renderDmgToggle` on `0..N` jumps off ↔ max unless the dep sets `cycleRanks:true`.
  * Item = 40px icon (grayscale when off) + `label` + effect tags `CD CAST DUR CHANCE DMG HITS KO SHIELD STATS INFO`, coloured by stat. A dep used at several sites shows once with merged tags.
  * A rank dep may give `iconFor(rank)` / `labelFor(rank)` when its icon or label is not `<icon base><rank>` (Chameleon Piercing Venom / Deadly Venom, target poison level 0-6, crit bow). A duration/cd dep may give `addFor(rank)` for a non-linear addend (Increased Poison 0-3 / Deadly Venom: +2/4/6/10 s). Name a passive's dep id after its card (`increasedPoison` → `chameleon_increasedPoison`) so `[DEP BACKLOG]` resolves it.
  * **Order:** `renderDepStrip()` sorts skill toggles ascending by internal skill ID (`SKILL_INTERNAL_ID`, card id -> lowest `commandNum` of the family in `<Class>Skill.cs` `getSkillTree()`). A toggle is matched to a card by `<class>_<dep id>`, `common_<dep id>`, or its icon key without the rank digit. Gear, target-condition and mode toggles (`DEP_NOT_SKILL`, or no match, or the selected card itself) follow in insertion order. Each item carries `data-dep-order`; a new card needs a `SKILL_INTERNAL_ID` entry (`[DEP ORDER ERROR]`); a new condition toggle that borrows a skill icon goes in `DEP_NOT_SKILL`.
  * Add deps via `renderDmgToggle(dep, TAG)`, `renderDmgRankToggle(dep, TAG)`, `renderDepBlock(dep, rank, "", TAG)`, or `depSinkAdd(dep, TAG, html)`. Non-dep controls (SP/HP/weight/height inputs, Nine Steps rows) stay in the damage header. `[DEP STRIP ERROR]`.

## Reach badge and popup (2026-10-13, user)
* A card with a `reach` field shows `.sk-reach-badge` (gold, KO-badge size) after the cost badges in `.sk-hero-sub`; a click (delegated on `displayEl`) calls `openReachPopup(activeSimSkill(), rank, hooks)`; `hooks` = `getRank` / `setRank` (writes `depRanks`, applies `DEP_EXCLUSIVE`, `renderHero()`) / `skill` / `rank`, so the popup changes the real card state.
* **The model is rasterised by hand (`reachRender`, user 2026-10-13: no seams, better lighting).** Per-triangle canvas clipping left light seams at every shared edge (anti-aliasing blends along each clipped edge) and cost 11.7 ms per redraw (91% of it). Now one z-buffer for all parts (body + hair), barycentric coverage (a shared edge is covered exactly once), the skin sampled per pixel (nearest, bilinear when magnified), Gouraud lighting, and the result is put into a reused buffer and drawn once. **Lighting:** corner normals averaged across gentle angles only (< 50°, `t.vn`, computed at load) so spikes and creases stay crisp; light follows the camera (key from the upper left, soft fill from the lower right, sky / ground ambient `0.5 + 0.12·n.y`, capped at 1.15, 0.6× when seen from under the ground). **Interleaving with the translucent boxes:** boxes farther than the caster's centre are painted before the model, the rest after. **Speed:** small models render at 2× and are averaged down (smooth silhouettes), big ones at 1×; an adaptive quality `reachBuf.q` (0.45-1) drops when a frame takes over 10 ms and rises again under 4.5 ms; the backing store is capped at 1.5× device pixels; input handlers use the coalesced `redraw()` (one draw per frame), animation loops `drawNow()`. Measured at 1254×605: close-up hold 8.9 ms, orbit 3.4 ms, default view 1.2-2.5 ms (a wrapper on `window.drawReach` times it; the page itself is unaffected, reach code is ≤0.7 ms per card render).
* **Size and layout (user 2026-10-13, reworked 2026-10-14):** **No containers (user 2026-10-14): the canvas is the whole popup, full viewport (`.sk-reach-pop` > `.sk-reach-panel` is `position:absolute; inset:0`, no background, border, padding or radius), over a 94% black backdrop. The toggles (`.sk-reach-head`), the legend (bottom left, one column under 900 px) and the `WASD` hint float over it with a dark text shadow; there is no skill name and no close button.** The default zoom scales with the canvas (`min(w/494, h/371) x 1.3`) so shapes keep their proportions. **Intro** (only for a class with a model; others just fade the boxes in; user 2026-10-13: one continuous move, no long first freeze): a 120 ms beat on the close-up of her face from the front (`yaw 0`, zoom `canvasW / model.view`, look-at height `model.focus`, `st.t[2]`), then a 1700 ms eased orbit + log-space zoom-out to the default view (`yaw π − 0.5`, i.e. from behind so she faces away and the boxes run into the screen). The slow drift (0.1 rad/s) fades in from 55% of the orbit (smoothstep over 1100 ms) so the camera never stops, and the boxes fade in on top of that motion from 68% of the orbit (850 ms, alpha 0 → 1, sizes ×0.9 → 1). The intro clock waits until the skin is loaded (`model.ready`), the model is decoded in idle time when a reach card is shown (`reachModel(cls)` from the hero render), so the first draw comes 15 ms after the click. When the intro ends the view is NOT reset: `startAuto()` carries on at the same speed. **Only W A S D and orbiting stop the intro and the drift (user 2026-10-13):** a W / A / S / D key or a single-pointer drag that actually moves (`endIntro` resets to `home()`, `stopAuto`). **Scrolling, pinch-zooming, double-click reset, a plain click, the arrow keys and every toggle never stop them:** the wheel / pinch go through `zoomBy` (during the intro they multiply a user factor `zoomK` that the intro frame applies on top, afterwards they change `st.zoom`), double-click reset is ignored during the intro and resets the view otherwise while the drift carries on. A toggle during the intro only updates the values (`parts`, legend, `st.ms`) and the boxes fade in with them (no volley while `introing`); after the intro the volley plays and the drift keeps going underneath it. Plays on every open.
* **Canvas:** `.sk-reach-pop` > `.sk-reach-panel` (4:3 canvas, legend `reachPartLabel`, hint). Painter's order, farthest first (`reachProject` depth: larger = nearer). Drag rotates: yaw free, **pitch -1.45..1.45, so the camera goes under the ground** (user: see how much of a box is buried); wheel / pinch zooms 6-400 px per m; double-click resets; **keyboard (user 2026-10-13, simple like the Golden King Bug map and used together with the mouse):** W / S walk the look-at point forward / back along the view, A / D strafe, speed 0.3 view-widths per second, eased (0.12 lerp per frame) and read by `e.code` (Thai layout works); the mouse still orbits, the wheel zooms, double-click resets orbit, zoom and pan; the ground grid follows the look-at point. `reachProject(v, yaw, pitch, zoom, w, h, t)` takes the look-at `[x, z]`. The arrow keys do nothing here but are swallowed in the capture phase while the popup is open, so they cannot switch the skill behind it; Esc closes, and so does a plain tap / click on the scene (one pointer, moved under 4 px, under 300 ms; it closes after 320 ms so a double-click reset or a drag cancels it). Every face and edge is split at y = 0 (`reachClipPoly` / `reachClipSeg`): with the camera above, the buried pieces are drawn first, dimmed with dashed edges, then a translucent ground plane + 1 m grid, then the rest; from below, the reverse. Sizes tag the far end of each part, rounded to 0.1 m while morphing.

## Popup performance (2026-10-14, user)

* **No `backdrop-filter` on any overlay or popup.** A full-viewport `backdrop-filter: blur()` makes the browser re-blur the whole (huge, scaled) page behind it on every frame while the popup animates in; the server-balance popup and the Buff / Debuff panel lagged very hard until the blurs were removed. Dim the page with a plain `rgba()` background (raise the alpha a little to compensate). A second blur on a ~98%-opaque popup panel is invisible and pure cost. Validator `[PERF ERROR]` fails on any `backdrop-filter` other than the theme variable `var(--th-blur,none)`.
* **Animate `transform` and `opacity` only** (the popup pop-in does). Keyframes on `box-shadow`, `filter`, `background` or layout properties repaint every frame; keep them short (the delta pings) and never `infinite` on the main page. Known leftovers: `simGlow` on `.sk-simulate-btn.is-new` (infinite `box-shadow`, only until the first Test click).
* A popup must not rebuild or re-render more than it shows: `renderBdPopup` rebuilds its whole `innerHTML` (every item's data-URI `<img>`) on each toggle and `renderHero()` follows; measured ~5 ms per click, fine today, but do not add more work there.

## Target value on a stat chip (2026-10-08, user)

* Clicking a **Cooldown / Cast Time / Duration / chance** chip (`.sk-target-chip`: pointer cursor; on hover only the number glows (`text-shadow`), no chip fill and no transform because the stat tooltips are `position:fixed`, no icon; chips with no stat effect, `.sk-stat-value.unwrapped`, are not clickable) edits **in place** (`openTargetEdit`): the chip's coloured number is swapped for an input that inherits its font and colour (no box, no range hint, no buttons). Enter or clicking / tapping away confirms (an unchanged or invalid value just closes), Esc cancels. The reachable range, the flat check and the clamping are checked on confirm and reported by the toast. The user types the value they want; it is clamped to what the formulas can reach, then the smallest stat that gets there is written into that stat's input: CD → AGI, cast → INT, duration → CHA (TAL with `durAdjust:"tal"`), chance → LCK. Phoenix / Monkey own-stat cooldowns are skipped.
* **How it solves** (`solveTarget`): it does not re-implement the formulas. It binary-searches the stat (0 .. 512; **AGI has no cap**: the search widens ×4 up to a 1,000,000 limit, so it can run wild), each step typing the stat in, setting LCK = 0 (no luck spread, so the chip shows one number) and calling `renderHeroNow()`, then reads the chip (`chipNumber`: the worse end of a range). Dependencies, Revised Art, buffs and the enemy target are respected for free. **The direction is measured, not assumed** (`targetRange` compares the chip at stat 0 and at the cap, `info.dec`): Bat Doom's duration is contested the inverted way (more CHA = shorter), flat post-added durations and floored steps (cast time falls in whole seconds) come out right because the chip itself is the formula. Checked on every chip of all 625 skills (no errors; cast time lands on the whole second at or below the wanted value). `withProbe` restores the stat and LCK and re-renders, so the card's real state, and the delta-motion snapshot, are the original ones before the real change is made.
* **Side effects (user decision):** only the one stat input changes; LCK keeps its real value. The write is a real `input` event (card re-renders with the delta motion, the preset autosaves) preceded by `presetPushUndo()`, so **Ctrl+Z** restores it. A toast (`.sk-target-toast`) says what changed, or that the value was clamped / the chip does not depend on the stat.
