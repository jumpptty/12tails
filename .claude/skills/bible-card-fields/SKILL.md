# Bible: skill card schema and card fields

Part of the Bible rulebook (core rules: [12t_projects/bible/CLAUDE.md](../../../12t_projects/bible/CLAUDE.md)).

## Card fields for notes and adjusters
* **`reach: part | [part,...]`** (card field, 2026-10-13, user): the skill's hit volume, shown as the small `.sk-reach-badge` in the hero header (headline size, e.g. `r 5m`, `6×2×3`, `40m`, `ตัวเอง`, `?`) and as a rotatable 3D shape in `.sk-reach-pop` (custom canvas, no library). A part is `{shape, r, h, w, w2, l, angle, z0, anchor, label, rangeMod, src, unknown}` (`w2` = full width at the far end of a `FindRecTarget` trapezoid, default `w`; `z0` = start offset along the facing in metres, negative = behind the caster; `x0` = sideways offset in metres in the popup space (a row of side-by-side blocks such as Penguin Ice Block, a scatter square such as Falling Comets; most cards never need it); `FindRecTarget`'s width arguments are half-widths, so `w = 2×BaseWidth`, `w2 = 2×TopWidth`; box and cylinder heights are drawn over the real band `[−0.5h, +h]`, see 12Tails-Mechanics-Reference.md §4): `shape` = `sphere | cylinder | box | cone | line | self` (`sector` = a flat fan of `angle` degrees; with `r0` it is a crescent between the inner radius `r0` and the outer `r`, Wolf Twin Resonance); sizes in metres (full width / length, `angle` in degrees), any of them may be `(rank)=>n`; `y0` = metres the game moves the Find* position up (+) or down (-) before taking the vertical band (Wolf Charge Attack `-2`, Mass Resurrection `-4`; not scaled by rangeMod); `shape:"ring"` = a flat circle on the ground, outline only and faint (a target lock `r 40`, or a flat distance gate such as Raijin Ken `r 35`; never a line, user 2026-10-14); `steps:[d,...]` (or `()=>[...]`; an item may also be an object of part overrides, e.g. `{r, label}` for a growing fan such as Twin Resonance) = forward distance in metres the caster has travelled from the cast point at each hit: the popup draws one copy of the part per step (same colour, `z0 += d`, caster stays at the cast point), for a dash that carries its hit box (Wolf Feral Strike one step 4.8 m, Feral Assault boxes every 4.2 m; derive d from the decompiled `moveSpeed` x wait time: `reachPath([[speed, seconds], ...], [hitTime, ...], base, tbase)` does the sum and also returns `.at` = the game time of every hit (a `steps` array may carry its own `.at`; a part that is not a `steps` copy can set `at` itself, Cat Moon Storm; **same-spot repeated hits use `steps: () => reachAt([t, ...])`** (one copy per time, label and place unchanged, one legend line; user 2026-10-16: the playback must show every hit the damage sim counts, so a multi-hit card whose hits have fixed times needs them, checked against `hitCount` for every class); projectiles whose hit time is the flight time, random targets, AI / charge / hold-driven loops and single-target hits stay static); a combo chains its stages with `reachChain([{ legs, end, start }])` (`o[k]` = metres and `o.t[k]` = seconds stage k starts at, pass both on; `start` is the game's anchor for that stage, from the first stage's start: stages after the first wait for `actionTime - Time.time + X`, mechanics reference §4.8, and each stage's own waits before it moves or hits must be in its `legs`) and scales it by `moveMod` (Wolf Lunar toggle); read the state machine, the speed set in state k runs until the next `Yield` returns; `moveMod` cancels only where the code divides by it, like Feral Assault); **Playback:** every part with `at` is shown one at a time in the popup (see the skill page UI skill); `final: false` on a `steps` object keeps a round out of the final picture (Twin Resonance shows 40 rounds, five stay); `sn` on a `steps` object sets the legend's hit count when several copies are one hit (TTO Mole War Area: 4 fire pools burn together, so 144 copies are 36 burns). `noZoom:true` keeps a part out of the popup's default zoom and the badge text (an enormous faint search range such as Whale Bubble Burst's 200 m); `faint:true` makes any part edges-only, dashed and half opacity (the two true-3D gates, Wolf Art Breaker / Grand Cross, are faint `sphere`s of r 30); `shape:"tube"` = a moving trigger collider's corridor `{r, l}` along the facing at chest height (`y0` default 1 m), a true 3D volume with no vertical band, only for a wide collider (about r 0.5 and up, see the measured table in 12Tails-Mechanics-Reference.md §4); a `Physics.Raycast` projectile stays a `line`; `shape:"sector"` = a flat fan `{r, angle, h}` centred on +z (Wolf Twin Resonance, `Damage.FindAngleTarget`: angle test `< 0.5 x TargetAngle`, the usual band); `h:"inf"` = a flat `findEnemies` range (drawn 6 m tall, labelled ไม่จำกัดความสูง); `anchor` = `self | target` (the position the game's Find* call uses is the caster's own transform, `KOIRnET4pM` / `xouZty6Gud = this.transform`; there is no fist position, corrected 2026-10-13) (`target` and `fist` are display positions); `rangeMod` = which sizes the code multiplies by the caster's `rangeMod`: `true` = r / w / w2 / l / h, or a list of those keys plus `z0` (Water Monkey `["h"]`, Stasis Blow `["l", "h"]`, Combo stages 3-5 `["w", "w2", "l", "h", "z0"]` because they start 1×rangeMod behind the fist); a size with a fixed addend (Qi Strike `1×rangeMod + 5`) is computed in a `(rank, rM) =>` function and left out of the list; `src` = `file:line` (required unless `unknown`); `fit: <metres>` = how far a chain of repeated parts reaches (Blazing Arrow's 12 circles, the runic trail), so the popup's default zoom frames all of it (the normal zoom never goes below 8); `yBand: [lo, hi]` = the exact vertical extent in metres of a trigger collider read from a prefab (Monkey runic pieces, Rabbit potions), instead of the Find* band; `unknown:true` when the size lives only in a prefab (badge `?`, no shape). A `FindAreaTarget` circle is a cylinder (radius + `TargetHeight`), a `SphereCollider` / full-3D distance check a sphere, a flat `findEnemies` range a cylinder with `h:"inf"`, a cast / target distance a `line`. The desc never repeats the size (`bible-desc-writing`). Every card is reviewed one by one against `DecompiledSource/`, never bulk-parsed. `reach` may also be `(rank) => parts` when other skills change the size (Spirit Fist, Ogre Impact, Qi Burst, Force Gauntlet...); `reachControls: [dep | {dep, onRank, offRank, label, icon}]` lists those toggles for the popup (and plain deps for the damage header). Reach goes on the parent skill only, never on the passive that modifies it. A sphere is centred on the anchor's feet (a full-3D distance between transform positions). Functions: `reachNormalize`, `reachBadgeText`, `reachMesh`, `reachProject`, `openReachPopup`. Validator: `[REACH ERROR]` (shape, dimensions, anchor, src), `[REACH DESC ERROR]`, `[REACH BACKLOG]`, golden geometry. Spec: `docs/superpowers/specs/2026-10-13-reach-badge-design.md`.
* **Reach backlog rule (2026-10-15):** `[REACH BACKLOG]` flags an active card (not passive, not a `_zombie` AI list) with no `reach` whose desc states a size in any common form (`**Nm**`, `รัศมี`, `กว้าง`, `ยาว`), not only the old three phrases. Placement spots (potions, mercenary / clone spawn points), AI range thresholds (Barrel Bot, King Kaiser) and warp lengths (Blink) are drawn too, as faint rings / markers; `REACH_BACKLOG_EXEMPT` in `scripts/validate_skills.js` is empty and should stay so (a modifier such as Qi Burst draws its own copy of the parent's shape; a height condition such as the Tiger Toss climbs is a faint marker).js`. A single-target lock spell (target-mode skill, ally or enemy) gets `() => [REACH_LOCK40]` and loses its "ระยะ 40m" text; a cast gate is a faint `ring` (flat distance) or `sphere` (3D distance); a projectile whose size lives only in a prefab is `{ shape: "line", unknown: true, ... }`. A `reachControls` dep whose id equals the card's `castDep` / `dmgRankDep` id (Improved Slayer) is a popup-only handle: the header does not draw a second RANGE toggle for it. Far Reach-style modifiers are `reachControls` instead of `descDep` once the parent desc drops its sizes (delete `descDep`, pass `--allow-field-loss=<id>:descDep`).
* **`reachModel: "<Name>"`** (card field, 2026-10-15): draw this `REACH_MODELS` entry (a summon such as `"BarrelBot"`, `"Gaos"`, `"LightGolem"`, or a lender class for the Common borrowed-power skills) in the range popup instead of the class model, for skills the summon attacks with or whose area is centred on the summon. The validator fails when the key has no model. Part keys added the same day: `yaw` (degrees) and `h: "inf"`.
* **Card notes fold into chips (2026-10-08, user: they cluttered the default view):** `tooltipNote` (`ⓘ คำอธิบายไม่ตรง`), `bbBug` (`🐞 บั๊ก`) and `unintended` (`⚡ ไม่ตั้งใจ`) render as one small chip each (`.sk-note-chip`). **Icon only, in the head line (user 2026-10-26, from screenshots; for a few hours the same day they stood in the gutter left of the desc box):** the chips are the head's last `.sk-hero-sub` group (`<div class="sk-hero-sub sk-note-chips">`, `noteChipsHtml` right after the costs, so after a hairline on desktop and phones alike), with no pill and no label (the label is the button's `title` / `aria-label`), after the in-game tooltip button (icon H); the icons are solid shapes (`NOTE_ICO`: a disc with an "i" hole, a bug with a seam hole and stroked legs, a bolt; the BB issues page shares them), 18 px in a 20 px button with a soft dark drop shadow so they read on the wallpapers. **Notes open in the in-game tooltip modal (user 2026-10-27; replaced the 2026-10-08 fold-out into the desc box):** a click on any note icon (or on H) opens one modal with the game's tooltip and every note of the card (bible-skill-page-ui, "In-game tooltip"); nothing opens inside the desc box, so the desc never grows. The note spans keep their classes inside the card's `<template class="sk-gametip-tpl">`, so validators that read the rendered HTML still find them; `[DEP STRIP ERROR]` fails a note rendered anywhere else on the card. `liveCheck` stays inline.
* **`bbBugSee: { id, text }`** (card field, user 2026-10-24): the same red 🐞 pill on a card that is *affected* by a bug whose full `bbBug` lives on another card (`id`). `text` is a short pointer that names the owner in `**bold**` (so it links) and says what is wrong for this card. Not listed on the BB issues page (the owner already is); validator check "bbBugSee points at a card that owns the bug". **The pointer follows its owner on the shown server (user 2026-10-28):** it shows only while the owner's view on that server (`getActiveSkill`) still has its `bbBug`, so a Reborn tab that clears the owner's bug (`bbBug: ""`) hides every pointer to it there, with no override on the pointing cards (validator: Double Cast on BB vs Reborn). Today: Double Art and Sublime Art -> Twin Resonance, Double Cast and Triple Cast -> Parallel Shift, Whale Combo -> Wall Puncture.
* **`liveCheck: "<Thai text>"`** (card field): a value nobody can derive from the code (e.g. a private-server patch that gave no numbers, `servers.tot.liveCheck` on Twin Resonance). Renders as the last line of the description box, `⚠ ยังไม่ยืนยันในเกม: …` (`.sk-live-check`, `--seal`). **A Thai tooltip that disagrees with the code is a `tooltipNote`, never a `liveCheck`** (all eight former tooltip liveChecks were converted 2026-10-02). `[LIVE CHECK ERROR]`.
* **`tooltipNote: "<Thai text>" | (rank) => string`** (card field): the in-game tooltip states a misleading value or rule (base duration, damage, chance, a missing or wrong effect) and the code is verified. Shows as the blue ⓘ icon in the head line and, in full, `ⓘ คำอธิบายในเกมไม่ตรงกับโค้ด: …` (`.sk-tooltip-note`) inside the in-game tooltip modal, in the **blue** signature colour `--tip` (user 2026-10-09; bug stays red `--seal`, unintended gold; `[NOTE COLOUR ERROR]`), also on the BB issues page; a rank-gated note returns `""` for ranks that match. Phrase it "บอกว่า … แต่โค้ดจริงคือ …" with `**values**`. **Several mismatches = a numbered list (user 2026-11-03, every card and server tab):** `"<br>1. บอกว่า … แต่โค้ดจริง …<br>2. ไม่บอกว่า …"`, one mismatch per item, each claim paired with its own code fact; the leading `<br>` puts item 1 under the label (the BB issues page drops it). A single mismatch stays plain text, and so does a lone garbled-row line on a TTO tab. **Compare against the Thai tooltip only** (`<Class>Skill_thai.cs`): players do not read the English one, so a mismatch that exists only in `<Class>Skill_eng.cs` is not listed, and the note quotes the Thai values. A mismatch never goes inline in the `desc` as a red `__คำอธิบายในเกม…__` line (all 50 were moved into `tooltipNote` 2026-10-02); `[TOOLTIP NOTE ERROR]` fails on an inline one and on a `tooltipNote` that renders at no rank. **Omissions go on the card too (user 2026-10-26, widened 2026-10-27):** when the Thai tooltip leaves out something about what the skill does (who it reaches, a multiplier, a duration rule, a cap, which hit gets the bonus), the card gets a `tooltipNote` phrased "บอก(แค่)ว่า … แต่โค้ดจริง …" (first: Chameleon Omni Slayer, Wolf Alpha Howl; Wolf Second Wind's missing **10 × level** cap). There is no "omissions stay in the class reference" exception any more (user 2026-10-27: Second Wind was a huge miss). Every mismatch is also recorded in the class reference ("Tooltip mismatch" in the skill's section, or the file's "Thai tooltip mismatches" table).
* **Finding mismatches (2026-10-27 scan):** compare every number in `GAME_TOOLTIP_TH` with what the card shows at that level (rendered text with the tooltip template removed, plus the adjuster arguments of its damage / KO formulas), then verify each suspect in `DecompiledSource/` (the RPC call site gives `sLv`, often 1-based where the formula reads `90 × sLv + 90`). The number scan cannot see a mismatch about *who* gets a number (Three Knives' +6 on the centre knife only), so read the text too.
* **Read the tooltip the way the game writes it before calling a mismatch (user 2026-10-27: Heavy Built was a false positive; 9 notes removed):**
  * **A step, not a total:** one line serving several levels, or "อีก N" / "ขึ้นอีก" / "ลงอีก", means one more N per level ("เพิ่ม hp … อีก 50%" = +50 / +100% at levels 1 / 2; Bison Improved Swing "อีก 5%" = +5 / +10 / +15%; Mole Speed Drill "ลงอีก 25%").
  * **A percent of a 0.5 × ATK hit:** "N% dmg" is often measured against a normal 0.5 × ATK hit, so `0.25 × lv × ATK` is "50% / 100% dmg" (Monkey Damage Cast, Rabbit Charge Attack, Chameleon's −0.025 × ATK steps = "−5%"); +0.1 ATK is "+10%" (Bison Spin Hack).
  * **"N% ของเลเวล" / "ตามระดับเลเวล"** means N / 100 × character level (Rabbit Bouncing Bullet "50% ตามระดับเลเวลกระต่าย" = 0.5 × Lv).
  * **"lv skill"** can mean the level of the status a target carries (Cat Open Wound: the Bleed / Disarm levels).
  * **An ambiguous sentence is not a mismatch:** note it only when no reasonable reading fits the code (Mole Fire Barrage's "หลังจาก 2 วินาที" can mean the plane arriving).
* **`durAdjust: "tal"`** (card field, default CHA): the Duration chip runs `talAdjust` with the player's TAL instead of `chaAdjust`, wears the TAL colour (`.sk-stat-dur-tal`, value and accent bar) and makes TAL glow instead of CHA (`getUsedPlayerStatKeys`). Used by Stun Mine on BB (`Mole_stunMine.cs:60`, a BB bug: Landmine uses `chaAdjust`). `[DUR ADJUST ERROR]`.
* **`durContestFn: (base, casterCHA, targetCHA) => seconds`** (card field, also on `secondaryDuration`; user 2026-11-03, ToT Bat C6): with `durContested: true`, the contested time comes from this function instead of `debuffAdjust` (Damage.getDebuff), through `contestDur` in the Duration chip, the second chip and the `hitCountDuration` hit count. For a skill whose code sets its own CHA-difference time: ToT Shadow Realm `clamp(15 + trunc((CHA − target CHA) / 10), 1, 45)`, Soul Capture `BAT_SOUL_DUR` (/ 20, 1-30; its Blind / Confuse / Curse chip adds `durPostAdd: 5`). `[TOT C6 ERROR]` pins both.
* **`unintended: "<Thai text>"`** (card field, 2026-10-08): behaviour that follows from the code but cannot have been intended (side effects between two systems, an internal status that the generic purge can reach). Renders gold under the desc as `⚡ พฤติกรรมที่ไม่ตั้งใจ (BB): …` (`.sk-unintended`) and lists on the BB issues page as its own type. Use it instead of `bbBug` when no single line of code is "wrong" by itself. `[UNINTENDED ERROR]` (validator §3t) covers the page and the card note; first uses: `whale_swallow`, `whale_gourmetHeart`, `whale_autoShield`. A card holding two findings joins them with `<br>` in the one string, each with its own credit token. A server override may make it `(rank) => text` when a toggle changes it (Reborn Gourmet Heart with Ocean Feast, 2026-10-26).
* **`bbBug: "<Thai text>"`** (card field): the BigBug client code itself misbehaves (a cooldown that is never checked, a bonus that is never applied, a level table that stops growing). Renders red as `🐞 บั๊กของตัวเกม (BB): …` (`.sk-bb-bug`). Cite the source in the class reference.

## Server-exclusive and coming-soon cards (user 2026-10-25)
* **`onlyServer: "<srv>"`**: the skill exists on that server only (Reborn C6 / C7, ToT EX). The server toggles show only that server's logo (`getAvailableServers`), the card opens on that server, and leaving it puts back the server the page was on before (unless another server was picked meanwhile).
* **`soon: "tot" | "reborn"`** marks a generated coming-soon stub (desc `เร็วๆนี้`, big gold desc, red roster border, roster tabs C / Common with the server's logo). Stubs are generated from `SKILL_SIM_EX` / `SKILL_SIM_REBORN_EXTRA` after `SKILLS`; the id is the icon key without its rank digit. A real card with that id (e.g. `rabbit_mixshot`) replaces the stub automatically; `SOON_EXTRA` adds fields to a stub (Eagle Eye's link back to Mix Shot). Stubs are exempt from the doc backlog and `SKILL_INTERNAL_ID`, and are not counted in skill totals.
* **Researched ToT EX cards (2026-11-02, Cat, Chameleon, Mole, Rabbit, Sheep, Whale):** each keeps the stub's id (`tot_ex_<name>`), its name and its icon, has `onlyServer: "tot"` and its cell in `SKILL_INTERNAL_ID`, and sits after the class's Reborn-only cards. Whatever `ToT_C6Data/` leaves out goes in `liveCheck` and in the class file's "ToT C6 skills" section; never guess it. **ToT1103 (2026-11-03):** the fuller batch `ToT_Skillsim_2026-11-03/` (AGENTS.md) answered most of those `liveCheck`s and the cards were corrected from it; a number only in the ToT team's notes (`C6_GAMEPLAY.md` …), not in the code, stays in `liveCheck` worded "ทีม ToT ระบุว่า …". Only the 454 cards carry `cdMapStart` (`ToT1103:START_COOLDOWNS.md`; the 2026-11-02 "every C6 cooldown" default was an assumption, user 2026-11-03: trust the code). **From the Wolf cards on (user 2026-11-03):** every fact the code does not show (a cost, a skill list or a status effect that only the team's notes give, the start-of-mission cooldown) is followed right there in the desc by `__ไม่สามารถยืนยันได้จากโค้ด__`; costs go in a `## ค่าใช้จ่าย` topic for that reason. Be complete: a fact the code shows is never left out (VoidBreaker5). **ToT1103S (the supplement of the same day, AGENTS.md):** its catalog confirmed every C6 cost and its `Start()` lists every 454 start-of-mission cooldown, so those `## ค่าใช้จ่าย` topics were removed; a number it gives only as a balance value whose reading code is missing (Shadow Realm's tick) says so in the line, and what it still leaves open keeps the mark.
* **ToT C6 toggles on original cards (user 2026-11-02; rewired from ToT1103 code 2026-11-03):** all in one table right after the stub generator in `index.html` (`totC6Toggle(id, dep, line, over, controls)`, deps from `totC6Dep`): it adds the card's `servers.tot` desc line (`totC6Line`, shown by its toggle), the reciprocal `compatSkills` and `changeNote: ""`, and appends to `dmgControls` (the toggle moves the damage row) or `infoDeps`. Wired from each `ToT_C6Data` file's comment and balance block; a number the excerpt's code states wins over the comment. Since 2026-11-03 every row follows `ToT1103:` code (the table's comments cite it): MissileBot5 is `afterDefMult` (bible-damage-model), PiercingKnight5's knight purple a fixed-chance `effectProc` on 12th Kingdom Knight only (Knight of the Deep and Immune Shot lost their toggles), PaydayShot5 wraps Rabbit Combo's `rawModel` (×1.25 floored, shotgun only). The team's balance values are the live ones (stormboy 2026-11-04: the server sends no other values; AGENTS.md). **ToT1104 (the follow-up of 2026-11-04):** it answered most of the remaining `__ไม่สามารถยืนยันได้จากโค้ด__` lines; a topic that only held team notes (`## ข้อมูลทีม ToT`) is renamed for what it covers once its lines are code, and a line the code still does not show keeps the mark. **ToT1104A** (the team's answers the same day, `ToT_Skillsim_2026-11-04_answers/`) left three marks: EarthQuake5's remote KO (both lines) and Soul Capture's last tick. What each toggle does and cites: the class file's "ToT C6 skills" section.
* **Data warning on ToT / TTO (user 2026-11-02):** `serverDataWarnHtml` opens the desc with a big `.sk-data-warn` line on that server's C6 cards (ToT: ข้อมูลคุณภาพต่ำ อาจมีผิดพลาด ข้อมูลมาจากโค้ดที่ไม่สมบูรณ์; TTO: ข้อมูลคุณภาพต่ำ อาจมีผิดพลาด ข้อมูลมาจาก Tooltips ในเกม), with a smaller `.sk-data-warn-sub` line under it on both (หากเจอข้อมูลส่วนไหนของสกิลนี้ ที่ไม่ได้ระบุไว้ในเว็บนี้ สามารถช่วยกันแจ้งมาได้ เดี๊ยวจะใส่เครดิตไว้ให้). A plain `เร็วๆนี้` stub has none. An original card shows it on that server's tab while a drawn toggle whose `icon` is that server's C6 card icon is on, so **a C6 toggle must use the C6 card's icon**, or the warning will not follow it. **`dataWarn: false` (user 2026-11-02)** drops the banner from a card checked against decoded client code, and its icon then no longer brings the banner onto original cards (first: Cat Royal Flush, checked against `TTO1102:`; the validator pins it). Such a card takes its cooldown chip from the code, not the C6 default below: `cdMapStart` only where `TTO1102:<Class>::Start` seeds the skill (Rabbit seeds Contract and Bounty Hunt only, so Medic Turret and Coin Ricochet have none; Penguin seeds Emperors March, not Constellation or Frost Field), and no cast time where the skill has no cast bar (Rabbit's Lv 100 skills only play an animation). On TTO every class seeds exactly one Lv 100 skill, its cell 454 (the list: 12Tails-Mechanics-Reference.md §4.12), so of the 36 cards only the twelve 454 cards carry `cdMapStart` (Royal Flush's was removed in the run's wrap-up), and a fixed cast that INT does not shorten is `castWrapped: false` (Mole Barrel Railgun's 6 s); a tooltip "เวลาร่าย" row can be a fixed impact time with no cast bar (Bison Titan Drop, Magma Quake: a desc line and a `tooltipNote`, no cast chip).
* **`soon: "tto"` (user 2026-10-31):** the TTO Lv 100 stubs, generated from `SKILL_SIM_TTO_EXTRA`, carry MP / SP, the site's text as a placeholder desc, and a `ประเภทดาเมจ` line (Physical / Magic), with no `liveCheck` (user 2026-10-31); roster tab C with the TTO logo. Magic ones are in `TTO_MAGIC_DMG`. Only a desc of exactly `เร็วๆนี้` gets the big `.sk-soon` look. Since 2026-11-02 all 36 TTO cells have real cards, so the generator adds no TTO stub (it skips an id that already exists); it stays for a cell a later TTO patch adds.
* **TTO patch notes (user 2026-11-02):** `ttoFix(id, note, fields)`, in a table right after the stub generator in `index.html`, adds a `[Fix]` line and the changed fields to the card's TTO tab, keeping its earlier note. Clear what the fix settles (`bbBug: ""`), keep what the note does not mention, and a line that gives no detail goes in `liveCheck`, with the card unchanged.
* **TTO Lv 100 cards from tooltip pictures (user 2026-11-02; on TTO this is history: since the client decompile the same day all 36 TTO Lv 100 cards are built from `TTO1102:` code, `dataWarn: false`, no `liveCheck`, so the steps below stay for a server or skill with no code):** a picture the user pastes becomes a real card with the stub's id, name and icon, `onlyServer: "tto"` and its cell in `SKILL_INTERNAL_ID`, after the class's Reborn-only cards. ## General card rules
* **No duration notes (`durNote`, abolished 2026-10-06, user):** the ℹ popup on Duration chips is gone (all 52 notes and the render code removed). Whatever a duration needs explaining goes in the skill `desc`; label the chip with `durLabel` / `secondaryDuration.label` (`"ระยะเวลา " + descriptor`, e.g. "ระยะเวลา Venom Shock").
* **Basic attacks, charge attacks and passives** get cards only when the user asks.
* **`statsTable: (rank, { LV }) => { mhp, atk, def, agi, vit, mag, cha, tal, lck }`** (+ optional `statsTitle`, default `<name> Stats`; 2026-11-02, TTO Rune Golem): a summon whose stats no move reads gets the reference Stats chip with all nine cells dimmed and no toggles, like War Capital; its damage stays on the player's stats.
* **Vertical collapse:** never render an empty `.sk-hero-stats` or `.sk-dmg-row`, no artificial min-heights.
* **`dmgGroups`:** must also declare top-level `dmg`/`atkCoeff`/`ko` mirroring the primary group (else `evalArith("")` SyntaxError). Sequential groups' `hitCount`s must sum to the top-level `hitCount(rank, dmgDepOn, hitCountDepOn)` for every dep combination (`[DMGGROUPS HITCOUNT ERROR]`); `dmgModes:true` cards are exempt. Declare `ko` per group when groups differ (`getGroupKOInfo()` splits/merges chips). **A `dmgModes` Test belongs to the skill whose hit it is** (user 2026-10-23): a mode that is really another skill's attack moves to that skill's card, with a `dmgRankDep` for the rank it reads (12th Kingdom Knight's former ชาร์จ mode is the Knight of the Deep card's own damage, `WHALE_KINGDOMKNIGHT_RANK_DEP`, like Grand Cross reading Cross Break). The `dmgModes` cards left are Monkey Planet Breaker and Reborn Chameleon Four Seals (judgement / death explosion, both its own hits) (inner / outer ring, both its own hit; the outer list is `Math.subtractArray(12 m, inner)`, so no target takes both in one pulse). **A `dmgModes` card shows one complete damage row per mode** (user 2026-10-23: "completely separated individual containers"): `renderHeroNow` builds the damage block with `buildDmgBlock(skill)` once per group of `dmgModeSkill(card, group)` (the group's `dmg` / `atkCoeff` / `ko` / `hitCount`, no groups, the group's `label` as a gold `.sk-dmg-mode-label` beside สูตรดาเมจ, `dmgRankDep` dropped when the group has no ATK term or `depLv`), and each row's Test bar rolls that group of the card (`simulate-group`, `data-group-index`). `[MODE ROWS ERROR]` checks one labelled row per mode with its own Test and every Test total inside its row's Final (the range-vs-simulator sweep skips `dmgModes` cards).

### Stat chips

* **Labels:** `lckProc.label` / `secondaryLckProc.label` / `tertiaryLckProc.label` are mandatory, format `"โอกาส " + <descriptor>` (`"โอกาส Frost"`), no "Chance"/"Proc" suffix (`[LCK LABEL ERROR]`). Duration labels (`durLabel`, `secondaryDuration.label`) use `"ระยะเวลา " + <descriptor>` (`"ระยะเวลา Ice"`), no English "Duration"/"Lifetime".
* **Cooldown toggles (`cdDep`, `cdMultDep`):** `cdMultDep` is a second cooldown toggle after `cdDep`. Kind `preCeilMultiply` (user 2026-11-01, Fire Keep) is `Math.ceil(raw × multiplier)` before `agiAdjust` with no rounding after it (`depPreCeil`, shared by the chip and the guide hover). Kind `postMultiply` floors after `agiAdjust` even at multiplier 1, so use it only when the source really does that.
* **Cast toggles (`castDep`, `castDep2`):** `castDep` is the card's cast modifier (Rapid Fire `perRank`, Improved Slayer, Reduced Cast `postMultiply`, Rapid Trance `replace` 0, Crown of Stars `postAdjustMul`). `castDep2` (user 2026-10-28) is a second cast toggle applied after it, raw-value kinds only (`replace`, `perRank`, `addFor`; `[CAST TOGGLE ERROR]` on a post kind), and it works with or without a `castDep`. Monkey Instant Cast (`MONKEY_INSTANT_CAST_DEP`) and Auto Instant (`MONKEY_AUTO_INSTANT_CAST_DEP`) always go in `castDep2`. A server tab inherits the base card's; `castDep2: null` in a `servers.<srv>` tab removes it there.
* **`secondaryDuration: {duration, durWrapped, durContested, label, show?, durMin?}`** → `.sk-stat-dur2`, for a genuinely different second duration (Frost Bite frost vs ice). `show: () => bool` hides the chip, e.g. while the toggle it belongs to is off (Reborn Doom's Doomsayer timer). `durMin` (2026-11-02) is a floor the code applies after `getDebuff` on a contested chip (TTO Barrel Railgun's paralysis: `max(1, getDebuff(2, …))`, so a target whose CHA is far above the Mole's still gets 1 s, not 0).
* **Reborn popup pointer (2026-10-26):** a card's Reborn server popup always ends with "สกิล C6 / C7 ของ Reborn ที่เกี่ยวข้องกับสกิลนี้: …" for the linked Reborn-only cards its change note does not already name; the "(เปิดสวิตช์…)" hint shows only when the card has a toggle for one of them (a dep with that card's id or icon). The auto-diff lines (cooldown, duration, cast) compare numbers only. **Common notes in the popup (user 2026-10-26):** under the card's own note, `serverCommonNotesFor(skill, srv)` lists every `COMMON_SERVER_NOTES` entry whose `id` test in `COMMON_NOTE_FOR` picks the merged card (TTO: LCK roll removed, gear LCK, Magic Damage; Reborn: item chances, SP ceiling, AI scan, stat caps, status merge, run speed, potion cooldown; seals and hit boxes have no test on purpose, user 2026-10-27: game-wide, noise on a card), so a card with no note of its own still opens a popup when one applies. A new common note needs an `id` and a test there, or it shows only on the server-changes page. **A card note never repeats a common note its popup shows (user 2026-10-27):** say only what is the card's own (Chameleon: Critical Plus joins the ×1.3 gear roll); when nothing is left, the override keeps `changeNote: ""`, which also stops the generic "มีการปรับเปลี่ยนเอฟเฟกต์…" filler line. **No same-formula lines (user 2026-10-26):** a common note never states that two things share a formula (the removed Reborn line "heals by TAL use the damage formula, so no 512 cap either"): it only complicates the text. The code keeps them apart anyway (`talHealAdjust` next to `talAdjust`), in case they differ one day.
* **Start-of-mission cooldown = a chip, never desc text (user 2026-10-26; replaced the C6 / C7 desc bullet of the same day):** a skill that enters every battle map on cooldown (the class `Start()` list on BB and Reborn, plus `RebornC7Act.Seed` on Reborn: [12Tails-Mechanics-Reference.md §4.12](../../../12t_reference/12Tails-Mechanics-Reference.md#412-start-of-mission-cooldowns-verified-2026-10-26)) shows it on its cooldown chip, and no text names the game modes (user: it always applies where it matters). Mostly Class-C skills, but the BB Class-B pairs count too (Support Fire, Dual Brand, ...).
  * **Same value as the card's cooldown:** `cdMapStart:true` adds `· ติด CD เริ่มฉาก` to the chip's base row (22 BB cards, 20 Reborn-only ones on 2026-10-26).
  * **A different value, or no cooldown of its own:** a second chip `secondaryCooldown:{ cd:N, cdWrapped:true, revisedArtExempt:false, label:"คูลดาวน์เริ่มฉาก" }`. Used for the Reborn C7 360 s set, ICBM 240, Iron Overdrive 300, Combo Link 600 (in `servers.reborn`) and Book Bash 60 (no cooldown of its own).
  * **Revised Art:** applies to both (`CharacterControl.addTimeOut`). `· revArt ไม่มีผล` (`revisedArtExempt`) sits on the same base row. `statBaseRow(lead, notes)` keeps each part whole; a part that wraps to its own line on a narrow chip drops its dot (`.sk-stat-bits`: clipped 1.1em gutter).
  * **Original card, new on Reborn:** the chip goes in `servers.reborn`, plus a change note `• [Nerf] ติด CD เริ่มฉาก **N วินาที** (เดิมไม่ติด ใช้ได้ทันที)`.
  * **A fifth chip on a four-chip card** (Heat Death) takes `stats5:true` with `chipCols:{cd:1, cd2:2, cast:3, dur:4}`, so all five share a row like Arctic Wind (3 + 2 on phones).
  * `[CD START ERROR]` fails a desc that states the start cooldown, `cdMapStart` on a card with no cooldown, both forms on one variant, or a lost note in the chip code.
* **`secondaryLckProc: {label, chance, applies, ...}`** → `.sk-stat-lck2`, for distinct chances per hit/mode (Spread Shot). Accepts `dep` (gates: off = 0%) or `deps:[DEP, ...]` (toggles shown in the chip, not gating; `chance`/`calc` read them via `getDepRank`). **`tertiaryLckProc`** (`.sk-stat-lck3`, `lck3`) and **`quaternaryLckProc`** (`.sk-stat-lck4`, `lck4`) have the same shape. All three render through one helper, `extraLckChip()`, which also takes `show:()=>bool` to hide the chip (Bison Combo's crit chip without gear).
* **Fixed chances (user 2026-10-27): `fixedChance(label, n, more)`** (next to `procChance`) builds a chip that shows `n` as is (`calc: (c) => c`), skips the LCK roll and leaves LCK unlit (`noLck: () => true`), reads "fixed N%" under the number and is not rolled by Test (`simulate: false`; a card whose damage uses the chance rolls it itself, e.g. Moon Blade's `hitPurple`). `more` adds `dep` (off = 0%), its own `calc` / `baseText` (Wolf Combo's Shadow Pack: 0% while Dark Edge is on) or a note (`fixed (12% + 8%) × 2`). A chance that is fixed only under a toggle keeps its own chip and adds `noLck: () => <toggle on>` (Auto Shield with Last Bulwark, the Reborn runes). First set: Moon Blade / Moon Storm / Lunar Tempest, Walking Arsenal (and Chameleon Combo), Runic Inferno / Bastion, Revert / Divine Benediction, Last Bulwark, Unyielding Oath, Eternal Dark Edge, Shadow Pack (and Wolf Combo / Charge Attack), Berserker Rush (Reborn), Carron Gambit's four coins, Double Effect (TTO), Zombie Bison.
* **`<=` rolls:** the game sometimes rolls `Random.Range(0,100) <= lckAdjust(n)` (Bison spin, Over Pride), which is one point more than the usual `<`. Show it with `calc:(c,L)=>c>0?Math.min(100,lckAdjustChance(c,L)+1):0`.
* **`lckProc.simulate:false`:** keep the chance chip but don't roll it in the outgoing-damage simulator (defensive/reactive procs, e.g. Wind & Cloud evasion).
* **`lckProc.chance: (rank, procDepRank) => n`:** dep-driven base chance, resolved before `lckAdjust` (Time and Tide 50% → 100% evasion).
* **`lckProc.depGates:false`:** keeps the `dep` toggle as an input to `chance(rank, procDepRank)` without turning the chip or simulator chance to 0 while it is off (Herb Finder's Big Bag modifier).
* **`lckOdds: (LCK) => [{label, pct, base}]`:** one `.sk-stat-odds` chip per outcome of a direct LCK roll, in its own `.sk-odds-row` (5 cols, 3 under 680px); `pct` to 1 decimal, 0% dimmed; makes LCK glow. Grand Casino Arcade's `CASINO_OUTCOMES` / `casinoOdds` / `casinoRoll` / `casinoRawRange` are the single source for chips, sim and range (a Doom spin returns 0; `range.zeroMin`). `[CASINO ERROR]`.
* **`atkCoeffProc:{dep, chance, coeff, label}`:** a per-cast chance to replace the ATK coefficient; formula shows `min~max` with `xATK / yATK` (talAdjust and flat-ATK cards alike), ranges include both, Test rolls `lckAdjust(chance)` once per cast. Sharing `dep` with `lckProc.dep` merges `DMG` + `CHANCE` tags.
  * **Per stage (`perGroup:true`, Bison Combo):** each `dmgGroups` entry carries its own `atkCoeffProc: ()=>coeff`, and the Test rolls once per game stage instead of once per click. Groups that are one stage in the game share a roll through the same `procStage` key (Spin first/second). Helpers: `resolveGroupAtkCoeffProc`, `resolveGroupAtkCoeffDisplayRange`.
* **`groupVariant:{base:(rank)=>%, inclusive, forceDep}`** (Bison Combo's 3rd attack): groups tagged `variant:"base"` / `variant:"alt"` are two outcomes of one per-cast roll (normal hit vs spin). `resolveGroupHitCount` zeroes the groups of the other outcome. `forceDep` on = always `alt`; otherwise each Test click rolls once (`groupVariantAlt` holds the roll while its hits resolve) and the Final range spans both outcomes. The card rows show the `base` outcome while nothing is forced. The top-level `hitCount` must follow the same state (`bisonComboHits`); the `[DMGGROUPS HITCOUNT ERROR]` check skips the other outcome's groups. `[BISON COMBO ERROR]` covers the Bison card.
* **`dmgRankDep.postTal:true`** (with numeric `mult`): multiplier applied to the already-truncated `talAdjust(...)` result before adding ATK (Time and Tide: `0.5×ATK + talAdjust(10×sLv)×(1+0.5×passiveLv)`). Not the same as the default inside-`talAdjust` multiplier.
* **Chip layout:** by default chips left-pack in DOM order (`.sk-stats-packed`: cd, cd2, cast, dur, dur2, lck, lck2, lck3). **A packed row with 1-3 chips fills its width (user 2026-10-18)** on the damage row's 2 + 1 + 1 columns: one or two chips take half the row each, three put the first chip on two columns (CSS `:has()` rules, from 681 px wide; rows holding the Stats chip `.sk-stat-bb` keep their own placement). A sweep of all 655 cards found no overlap and no chip outside its row. `chipCols: {cd, cd2, cast, dur, dur2, lck, lck2, lck3: N}` sets explicit columns (`chipColStyle(key)`), only for a non-DOM order, and turns packing off for the whole card, so list every chip. `stats5:true` widens the row to 5 columns (cd/cast/dur/dur2 in 1–4, `lck` in 5; 3+2 under 680px), only for a card that truly needs all five (Arctic Wind).

## Compatible Skills Navigation (`compatSkills`) Conventions

1. Every edge is reciprocated (A lists B ⇒ B lists A). Sibling mesh links allowed.
2. Header exactly `<p class="sk-compat-title">สกิลที่เกี่ยวข้อง</p>` (Prompt, gold 14px, then a fading gold rule via `::after`). No `LINK`/`MASS CAST`/`MOVES` badges.
3. **Open layout (user 2026-10-18, B2 of 4 mocks): no panel and no box per row.** `.sk-compat-chip` has no background, border or theme surface (it left `THEME_SURFACES` and the skill card's `--glass-gradient` rule). Each `.sk-compat-item` (min 40 px, 28 px with more than 8 skills) is a thin gold ring `span.sk-compat-ring` (34 px, 22 px compact; 1 px gold edge, `img.sk-compat-icon` zoomed 1.3× and centred by `centreRingImg`) plus `.sk-compat-name` with a soft dark text shadow (the names sit on the page backdrop). **Nothing clips:** no `overflow:hidden` and no line clamp, so a long name grows its row; the ring edge, the name shadow and the hover lift stay whole (checked on BB / ToT / TTO, desktop related rows and phone). **Hover** lifts the ring and the name 1 px (never the button itself), turns the name gold and brightens the ring; no glow, no fill. Keyboard focus: 2 px gold outline.
4. Grids: many → `.sk-compat-grid` (`auto-fill, minmax(170px,1fr)`); 2–4 → `.sk-compat-few-grid` (`auto-fit`, one row); 1 → `.sk-compat-single-grid` (max 340px; full width in the side panel).
5. **Listed only when the desc does not link it (2026-10-29):** the skill page shows a `compatSkills` entry only when the tab's desc does not already link it (`findSkillByMention`, hidden lines included); on desktop it is also left out when a skill toggle row can open it (it appears once, as that row), while phones list it anyway. More than 6 rows fold into `ทั้งหมด N สกิล`. Keep every edge in the data regardless: `findSkillByMention`'s tier 1 and `[COMPAT ERROR]` use it. Layout: bible-skill-page-ui, "Side panel".
