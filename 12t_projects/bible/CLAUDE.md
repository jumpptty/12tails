## 1. Large File Handling & Crash Prevention Protocol (~15 MB)

Since 2026-10-20 every game icon, portrait, 3D model and sound lives as base64 in **`assets.js`** beside `index.html`: one `BIBLE_ASSETS.<NAME> = …;` block for each of the 17 containers in `MANIFEST` in `scripts/bible_assets.js` (`SKILL_ICONS`, `CLASS_ART`, `CLASS_HERO_ICONS`, `CLASS_STORY_ART`, `REACH_MODELS`, `GEAR_ICONS`, …), one entry per line. `index.html` (about 4 MB) loads it with `<script src="assets.js?v=<stamp>" id="bibleAssets">` and declares each container as `const NAME = BIBLE_ASSETS_IN.NAME || {}`. It keeps only small inline data URIs (CSS art; budget 400 KB, `[ASSET BUDGET ERROR]`). Locate blocks with `grep -o`.

1. **Zero base64 ingestion:** never read, grep or dump the base64 blocks, in `assets.js` or `index.html`. Inspect icon keys with a small Node scratch script that prints key names only.
2. **Out-of-process patching:** every change to `index.html` is a small Node script in the scratch dir that loads the file, replaces the target in memory, writes it back and prints one confirmation line. No IDE edit tools on this file. For card fields use **`scripts/card_edit.js`** (`add-field` / `set-field` / `add-compat [--both]` / `replace`, `--dry-run`): it edits one card's top-level fields only (strings, template literals and `//` / `/* */` comments are skipped while scanning), backs the file up to `<os temp>/12t-bible-backups/` and refuses to save when the page script no longer parses (e.g. a raw line break inside a string). `node scripts/card_edit.js --selftest` checks it.
   * **One batch per change:** list every replacement first, dry-run so all anchor problems show at once (check match counts, not just presence; a pre-check must not match text the edit itself adds), apply everything atomically, then run the validator once.
   * **CRLF:** `index.html` is CRLF, and so are `scripts/*.js` and the Markdown rule files (`CLAUDE.md`, `AGENTS.md`, `CLASS-GUIDES.md`, the `bible-*` skills). In a patch script normalise both anchor and replacement to `\r\n` (a `\n` anchor silently fails to match). Count endings with Node (`/\r\n/g` vs `/(?<!\r)\n/g`): `grep -c $'\r'` in Git Bash reports 0. `sed -i` in Git Bash rewrites a CRLF file as LF. Write patch scripts with the Write tool, because a `node - <<'EOF'` heredoc mangles backslash escapes.
   * **Find a card by brace matching:** from `id:"<card>"` take the nearest `{` before it and match braces to its end (skipping strings, template literals and `${}`), then edit inside that span only. Never scan lines to the next `  {`: cards are often separated by `  }, {` lines, and a line scan once put Mimic's and War Capital's Reborn text on Dark Intention and Monkey's normal attack (2026-10-25). Afterwards list which cards carry the new key.
3. **Git checkpoint before every phase:**
   * A dirty `index.html` = uncommitted card work. Make a local WIP commit before running any patch script. Preserve unrelated changes; don't commit or revert them.
   * **Never run `git checkout` / `restore` / `reset` / `stash` on `index.html`.** Every patch script first copies the file to its scratch folder (`index.<timestamp>.bak`); recover from that copy.
   * **Never replace a whole card line.** Change only the specific fields (one `key:value`, one `compatSkills` id). Retyping a card silently drops fields.
   * `[FIELD LOSS ERROR]`: a card lost a field it had at `HEAD`. Deliberate removal: `--allow-field-loss=<cardId:field,...>`. `[DOC BACKLOG]` counts app skills with no class-reference entry (`--list-doc-backlog` lists them).
   * **Another session's work in the tree (user 2026-10-18):** when a parallel session has uncommitted hunks in `index.html`, commit your own finished work anyway. Build HEAD + your edits + the changelog entry, validate that version, and stage it alone (`git hash-object -w --path=12t_projects/bible/index.html <file>`, then `git update-index --cacheinfo 100644,<blob>,12t_projects/bible/index.html`; `--path` converts CRLF like `git add`). Write the same edits on top of the peer's working copy so its pending work stays. Re-check `git log -1` just before committing: if the peer committed in between, a version built on the old HEAD would revert it.
4. **Changelog entry & verification:** do not run `node scripts/guide_views.js` before commits any more (user 2026-10-20: skip the GoatCounter request, let the live API do its work; the `CLASS_GUIDE_VIEWS` snapshot for ad-blocked browsers is refreshed only by hand). Before committing, prepend a `CHANGELOG_DATA.entries` item with the current ISO timestamp and the **exact planned commit subject** (no `"` or `\` in it), then run `node scripts/validate_skills.js` (skills, formula permutations per rank and dep, icons). **The changelog entry is a habit, not a gate (user 2026-10-20):** the validator no longer checks it, because the gate hindered work in progress, but the user still wants the in-app changelog kept current, so add the entry with every commit that touches `index.html` (the guide manager `scripts/add_guide.js` does it for its own commits). `CHANGELOG_DATA.entries` is the **second** `entries: [` in the file (`CHANGELOG_ARCHIVE` comes first): anchor after `const CHANGELOG_DATA = {`, and keep the subject in a variable rather than reading it back from the file (a first-match read once sent a commit out with an old Sheep message). `skill-cooldown-lookup` is a protected branch, so force-pushes are refused: a wrong pushed message is fixed with a follow-up commit.
5. **Icons, art, models and sounds go to `assets.js`:** add or change an entry there with a scratch Node script (same backup rule), then run **`node scripts/bible_assets.js stamp`** so `index.html`'s `?v=` matches the new file, and commit both files. The stamp is what makes visitors fetch the new `assets.js` instead of a cached one; a stale one fails with `[ASSET VERSION ERROR]`, and anything but `BIBLE_ASSETS` data in the file with `[ASSET FORMAT ERROR]`. A new container goes in `MANIFEST` too. `node scripts/bible_assets.js --selftest` checks the tool.

## 2. Deliverable basics

* **Two files, no server (user 2026-10-20):** `index.html` plus its `assets.js`, opened by double-click. Without `assets.js` the page still runs, minus the pictures (console warning "assets.js did not load"), so code that reads a container must cope with it being empty.
* **No reduced-motion gates (2026-10-13, user: "bypass all reduced motion"):** every animation plays whatever `prefers-reduced-motion` says. Never add an `@media (prefers-reduced-motion…)` rule or a `matchMedia("(prefers-reduced-motion…")` check; the 10 CSS gates and the one JS check were removed. `[MOTION ERROR]` fails on any such rule or check (since 2026-10-23, after one slipped back into the ☕ ticker).
* **"Ledger" design system:** lacquer ground `#141311`, brass-gold `#d4af37`, oxblood `#8b1e1e`, high-contrast type. These are the base tokens; every server look overrides the palette, BB included since 2026-10-29 (the old TTO look, see bible-skill-page-ui "Server themes").
* **Hover = a small lift, never a gold glow (user, corrected twice by 2026-10-18):** a new hover state ("a subtle hover effect") is a `translateY` of a few px and/or a slight brightness change, never a blurred gold `drop-shadow` / `box-shadow` halo; no gold glints on ambient animations unless asked. Text shadows and outlines on round dials stay soft (about `0 1px 2px rgba(0,0,0,.4)`), never a heavy black halo.
* **Fonts: two only (2026-10-18, user).** Prompt for all text (UI, labels, headings, badges, popups, the "12 Tails Bible" logo); numbers use `'JetBrains Mono','Prompt',monospace`, always with Prompt behind it so Thai inside stays Prompt (a mono-only stack made Windows draw that Thai in Tahoma). No system stacks (`-apple-system`, Segoe UI, Consolas, `ui-monospace`, a bare `monospace`), no Georgia, Kanit, Cinzel, Inter, Sarabun; Google Fonts loads only Prompt and JetBrains Mono. Applies to CSS, inline styles, SVG `font-family` and canvas fonts; buttons and inputs inherit the page font. `[FONT ERROR]`. Chakra Petch stays banned too, even in mockups (`[FONT BAN ERROR]`).
* **Theme (2026-10-10, user): dark only, light mode abolished.** `<script id="themeBoot">` in `<head>` sets `data-theme="dark"` before first paint and drops the old `localStorage["12t-bible-theme"]`; there is no light / dark button. The top bar's server icon (`#btnServerTheme`) picks a purely cosmetic server look instead (AUTO / BB / ToT / TTO, `html[data-sk-server]`). New panels and modals must use the colour tokens (`var(--panel)` etc.) so they follow it; to give an element the glass / texture add its selector to `THEME_SURFACES`. Every element that paints `var(--panel)` / `var(--panel-2)` belongs in one of its groups (user 2026-10-17): `panel` (cards, wraps), `raised` (clickable), `popup` (menus, tooltips, pickers: texture and edge, own solid fill) or `field` (inputs, table headers: edge only). A pressed / active / disabled control keeps its own fill; to change a look edit its token block. See the Server themes section of [.claude/skills/bible-skill-page-ui/SKILL.md](../../.claude/skills/bible-skill-page-ui/SKILL.md). New colours need only the dark values (`:root[data-theme="dark"]`); the base `:root` block still holds the old light tokens, which the validator's theme-block checks read, so keep the token names in step. Every extra `<script>` must carry an attribute (an id): the validator runs the main app script as the text from the first plain `<script>` tag to the last closing tag, so a bare script tag, or that literal tag text in a comment, breaks it.
