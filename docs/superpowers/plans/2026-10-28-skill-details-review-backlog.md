# Skill Details: review backlog (2026-10-28, long-term revisit)

Five read-only reviewers (player UX, accessibility and phone, architecture, performance, correctness) critiqued the skill details tool on 2026-10-28. The quick wins went in the same day (first section). **Everything else here is parked for a long-term revisit: don't start an item unprompted; take it up when the owner asks or when a task touches that code anyway.**

- Line numbers are `12t_projects/bible/index.html` as of 2026-10-28 and drift; search by the function names.
- **(owner's decision)** marks a choice the owner made on purpose that the reviewers argued against. Reopen it only if the owner does.
- **Verified** = seen in the code or measured; **Inferred** = reasoned. Unmarked items were verified.
- Remove an item when it is done (git keeps the history).

## Done in the quick-win pass (2026-10-28)

`<html lang="th">`; the search term is escaped in the "no results" line; `route()` survives a bad `%` escape in the hash; the server pop-up and the Buff / Debuff popup are `aria-modal` (← / → no longer switch the skill behind them); the preset reset clears the buff undo stack; a lower server cap no longer eats CHAR LV (the wanted level comes back under a higher cap and presets save it); search starts at two letters; `aria-pressed` on dep toggles, server tabs and Revised Art, and rank selectors name their rank; leaving the tool closes its pop-ups (`closeSkillOverlays`).

**Not done on purpose:** a search debounce. A pending timer fires after a click on a result (`selectSkill` writes the name into the box) and would clear the card. Add it only with a cancel in `selectSkill` and everywhere code writes `searchEl.value`.

## 1. Data safety: presets, undo, storage (highest priority)

1. **Ctrl+Z restores the whole preset store.** `presetPushUndo` snapshots `JSON.stringify(presetData)` (every class) and `undoPreset` writes it back, while autosaved stat edits and name / description typing push no step. One Ctrl+Z (one too many while undoing buffs, or following the target solver's "Ctrl+Z ย้อนกลับ" toast) can wipe every autosaved edit since the last preset action, in all classes, with no redo. Fix: per-class, per-slot diffs; coalesced steps for autosave and label edits; each step tagged with its class, other classes' steps skipped.
2. **`undoBd` autosaves into whatever class is open** (`presetBdSeen = seen`): undoing a buff change after a class switch writes class A's old buffs into class B's preset. Fix together with 1.
3. **Two tabs overwrite each other.** `presetData` is read once at mount and every save writes the whole object (`12t-bible-stat-presets`; `saveCustomBd` the same for `12t-bible-custom-bd`); nothing listens to `storage`. Fix: re-read before saving and merge only the changed class / slot (or one key per class); reload on the `storage` event.
4. **Silent storage failures:** `catch (err) {}` around `setItem`, so a quota or blocked-storage failure looks saved until the next reload. Fix: a toast when a save fails.
5. **Autosave turns every "what if" into an overwrite (owner's decision: autosave, no save button).** Each stat keystroke rewrites the active slot (slot 1 by default), and the target solver's write autosaves too. Reviewers' options: edits as an unsaved draft (a dot plus บันทึก / ย้อนกลับ), or one undo step per field visit.
6. **One undo history.** Ctrl+Z takes the newest of three stacks (preset, enemy, buff) and covers neither dep toggles, the rank nor typed stats. A toast should name what was undone. Phones have no Ctrl+Z (put an undo button in the toast).
7. **`presetLoadAll` drops a whole slot over one bad field**, `active` can then point at nothing, and the next autosave makes the loss permanent; `loadCustomBd` drops entries the same way. Fix: fill missing keys with defaults; keep the raw data under a backup key when something is dropped.
8. **Stat inputs are not sanitised:** no max, `parseFloat` in the maths but `Math.floor` in the preset (AGI 150.9 shows 4.59 s, reloads as 150 = 4.6 s); AGI −128 shows "Infinitys"; the PRESET window clamps to 9999 without writing the value back. Fix: floor, ≥ 0, written back on input.
9. **Server state:** on a card without the current server's tab the row lights BB while the maths use the hidden server's LV cap, and clicking that BB counts as a change. `_selectSkillById` sets `currentServer = s.onlyServer` before `selectSkill` stores `serverBeforeExclusive`, so after a deep link to a Reborn-only card, → stays on Reborn.

## 2. Security

- The guide manager keeps its GitHub key in `localStorage["12t-gm-key"]` on the same origin as the Bible (`jumpptty.github.io`), so any script injection in the Bible can read it. The search one is fixed; audit the other `innerHTML` paths that carry user text (preset names and custom buff names were checked and escaped), and consider `sessionStorage` or a separate origin for the key.

## 3. Performance

1. **Biggest win: returning visitors re-download everything after every deploy.** GitHub Pages sends `Cache-Control: max-age=600` and stamps `Last-Modified` / `ETag` with the deploy time on every file (checked 2026-10-28: `assets.js` reported that morning's deploy, though it last changed on 10-27), so the `?v=` stamp saves nothing. At 3-29 pushes a day a returning player pulls about 21.6 MB gzip again (19.9 MB `assets.js` + 1.75 MB `index.html`). Fix: a small `sw.js` beside `index.html`: cache-first for `assets.js?v=*`, delete other stamps on activate, network-first for the page (no service worker on `file://`, so double-click keeps working). Alternative: jsDelivr commit-pinned URLs (needs the split below: 20 MB per-file limit).
2. **About 20 MB gzip blocks first use.** `assets.js` (29.5 MB) is a parser-blocking script before the app: `SKILL_ICONS` 13.8 MB (1,566 icons), `GEAR_ICONS` 6.3, `REACH_MODELS` 5.1, `CLASS_STORY_ART` 1.6 (only the preset window), `CHM_AUDIO` 0.6. Skill details never reads `GEAR_ICONS`, `CHM_AUDIO`, `DONATE_QR` or `TOOL_ART`; one class's icons are 0.9-1.7 MB. `assets.js` alone takes about 59 MB of JS heap (measured in Node). Fix: `bible_assets.js` writes a small core plus per-class / gear / reach files, added as `<script>` tags on demand (works from `file://`); turn the icons in use into Blob URLs once.
3. **Every keystroke re-parses about 120 KB of card HTML, about 71% data URIs** (median card 62.9 k characters, p90 133 k; the server tabs add 30-100 k because each logo is a 49 KB, 246 px image). Fix: Blob URLs (about 60 characters each), 64 px server logos, patch the server row instead of rebuilding it.
4. **The Buff / Debuff popup rebuild** is 196 k characters (182 k base64) per toggle, plus a full `renderHero`.
5. **Search:** two-letter queries can still be large. Cap or page the matches before building HTML; on phones `gridFitPaged` skips paging and lays everything out.
6. **Target solver:** up to 29 full rebuilds per edit (`targetRange` 3, AGI widening 6, bisection 18, final probe + restore), each forcing layout and queuing its own animation frame. Fix: a pure number function (the `*AdjustRange` helpers exist) or a probe flag that renders detached and skips layout and animation frames.
7. **Layout thrash:** `fitStatDials`, `fitDepLabels`, `fitFinalValues`, the hero name and the compat names shrink 0.5-1 px per step with a forced layout each; `positionStatTooltips`, `bdLvFit` and `deltaTag` read, write, then read again. Fix: measure once (`size *= clientWidth / scrollWidth`), reads before writes, skip dials whose value did not change.
8. **Delta snapshot cost:** `deltaFields()` runs 5 times per keystroke, with deep clones of every field and desc line; the 4 s safety timers keep the replaced card subtrees alive. Fix: snapshot model values (architecture 1), a generation counter that cancels old timers.
9. **Nested status tooltips:** Bat Nightmare builds 532 inline tips (4,554 elements) per rebuild, Mind Control 484, Charm 458. Fix: a `data-status` key in the markup and one shared pop-up filled from `STATUS_DESC_MAP` on open.
10. **Reach preview:** it warms up (models plus a 1024² terrain blend that allocates an array per pixel) on any of the 464 reach cards and is never freed; while open, the slow drift re-rasterises every frame. Fix: warm up on badge hover / pointerdown, bake the terrain blend offline, draw the drift at 10-15 fps or stop after one lap, free the caches on close. (Inferred phone cost: about 0.5-0.8 s.)
11. **`index.html` is 1.75 MB gzip, re-downloaded on every deploy** (guides and donors publish into it too): CSS 0.88 MB (16% comments), JS 5.06 MB (9% comments), other tools' data 1.72 MB (`GKB_PAYLOAD` 244 KB, `CLASS_GUIDE_STEPS` 224 KB, `CHANGELOG_DATA` 211 KB, `CLASS_GUIDES` 185 KB), and the ToT wallpaper as 247 KB of base64 in the head `<style>`. Fix: per-tool data in versioned side scripts; the ToT wallpaper into `assets.js`.
12. **Background work that never stops:** `simGlow` (infinite `box-shadow`; in private mode its "seen" flag is never kept), the menu's 700 ms / 3.5 s intervals all session, a window `wheel` listener with `passive:false`, and the class guide's document `touchmove` with `passive:false` that stays after leaving that tool.

## 4. Architecture

The refactor that would pay off most is 4.1.

1. **No model layer: the DOM is the data.** `renderHeroNow` (about 2,580 lines, 177 KB) both computes and renders, and the range maths are closures inside it. The target solver parses chip text, presets decide "lower is better" from the Thai label (`/คูลดาวน์|เวลาร่าย|cooldown|cast/i`), and the stat glow regex-scans formula strings. Fix (no build step): a pure top-level `computeCard(card, ctx)` returning `{fields:[{key, kind, value, range, lowerBetter, unit}], dmgGroups, desc}`. The renderer formats it and everything else reads it. That unlocks keyed diffs, DOM-free solving, golden-file tests and the script split.
2. **The damage pipeline exists three times** (`calcRangeFor`, `rollOneHit`, `renderOneDmgFormula`), plus Character Hit Mod copies (`defAdjust` vs `defAdjustAtRoll`, `chmAgiAdjust` vs `agiAdjustAtRoll`, one buff-delta expression copied three times). `--full` exists only to catch drift between them. Fix: one ordered stage list `{id, value, range, label}` that all three read (`rawModel.parts` already does this for 10 cards); Character Hit Mod calls the global `*AtRoll` helpers.
3. **A 7,987-line closure that depends on statement order:** 32 `let`, 17 `var` and 84 `const` at closure level, 38 of them reassigned from nested functions; 9 `var` hacks commented "renderHero() may run before this line"; 95 defensive `typeof` checks on the page's own globals. Fix: one state object at the top, `wire*()` functions, a single `start()` as the last statement, then delete the hacks.
4. **Per-card code in the engine:** 38 `.id === "<card>"` checks; the summon stats block is an id chain repeated four times; 12 `ownStats*` flag variants; 15 bespoke input `let`s (`pandaTargetHp`, `bisonHate`, `rabbitAimTime`, ...) although the generic `dmgInputs` (10 cards) exists. Fix: `summon:{title, stats(ctx), toggles}` on the card, inputs moved to `dmgInputs`, and a validator ratchet so the id-check count can only go down.
5. **Animation is snapshot, full rebuild, text diff,** with fields matched by position (the code admits mis-pings when a desc line is inserted), five readers stripping the roll layers, and `WORSE_WHEN_ON` (game meaning) inside the animation code. Fix: stable `data-k` keys from 4.1, diff model objects, patch values in place; `worseWhenOn` on the dep.
6. **The tests pin source text.** The validator rewrites the page script (`const SKILLS =` to `window.SKILLS =`, 49 `window._*` hooks injected at `function onSearchInput(){`), 189 assertions match raw HTML or source, and the stub DOM returns `[]` from every `querySelectorAll` with a no-op `setTimeout`, so the delta, carry-over, preset and target code never runs in a test. Fix: golden JSON from `computeCard` per card × server × rank; one explicit `BIBLE_TEST_API` object; optionally jsdom as a dev dependency (not a page build step).
7. **One 6 MB file makes every change collide:** 93% of the commits since 2026-09-28 touch `index.html`, and the patch protocol (CRLF anchors, brace matching, `hash-object` commits beside peers, the field-loss guard) is the workaround. No-build does not require one file: plain `<script src>` files load from `file://` (ES modules do not). Split into `skills-data.js`, `engine.js`, `skill-details.js`, `changelog.js`; the validator concatenates them the way it prepends `assets.js`; `card_edit.js` follows the data file.
8. **Servers:** `getActiveSkill` is a shallow `Object.assign`, so a nested override replaces the whole field (7 overrides copy a full `dmgGroups`); the ToT alias `skill.ps` is dead (0 cards, 7 references); 362 overrides build their desc by find-and-replace on the BB Thai text (`serverDescFrom` + `descSwap`), which throws when the BB text moves; server lists live outside `SERVER_INFO` (`LEVEL_CAP`, `THEME_CHOICES`, `SKILL_SIM_SERVERS`, `BD_SERVERS`, the reach popup's own list, `CLASS_GUIDE_SERVER_KEYS`, the order in `getAvailableServers`). Fix: `SERVER_INFO` carries cap, order and feature flags, every list derives from it, and the validator bans literal server arrays.
9. **Card functions read UI state through globals:** 309 `getDepRank` calls in `SKILLS`, the `reachDepOverride` back door, `liveStatReadsGlobal` / `getCharLvGlobal` / ...; the glow swallows errors (`catch (e) { live = null; }`). Fix: pass a `ctx` (`{rank, dep(d), stat(k), server}`); a codemod can rewrite `getDepRank(X)` to `ctx.dep(X)`.
10. **Primary and secondary chips are forks:** `cdBlock` vs `secondaryCooldownBlock` (21% shared) and `durationBlock` vs `secondaryDurationBlock` (26%); the secondary ones ignore `cdDep`, `durAdjust` and `talAdjustRange`; the schema has `secondaryLckProc` / `tertiaryLckProc` / `quaternaryLckProc`. Fix: arrays built by one chip builder and a load-time `normalizeCard()` that maps the old names. (The user-facing effect is Inferred.)
11. **Hand-kept registries in lockstep:** `DEP_EXCLUSIVE` written both ways by hand, `DEP_NOT_SKILL`, `WORSE_WHEN_ON`, `TTO_MAGIC_DMG`, `CAT_TREE_A_SKILLS`, and `SKILL_INTERNAL_ID` (pasted generator output, no generator in `scripts/`). Fix: attributes on the dep or card with the maps derived at load; commit the generator.
12. **The rulebook is a decision log:** `bible-skill-page-ui/SKILL.md` is about 135 KB / 21k words (one bullet is 11k characters) and `bible-hub-tools` 174 KB, so an agent loads 30-35k tokens before a first edit. Fix: a contract of at most about 150 lines per topic (the rules, the lockstep registries, where to change what), dated decisions moved to a `DECISIONS.md` that is not auto-loaded, mechanical rules turned into validator checks.

## 5. Player UX

1. **Which server are the numbers for?** The card's tabs run TTO / ToT / Reborn / BB but the Buff popup's BB / ToT / TTO; a card without the chosen server's data lights BB while the AUTO look keeps the old server; `bdServer` never follows the card and the Buff button doesn't show it. Fix: a text line on the card ("ตัวเลข: TTO (ใช้ค่า BB เพราะ TTO ไม่ได้แก้สกิลนี้)"), the Buff popup following the card unless pinned, its server on the button when the two differ.
2. **A hidden default build:** max rank, every dep off, Revised Art 5 on, all stats 128 at LV 100, target Carron with every stat at 2; the cooldown base line doesn't mention Revised Art; presets store neither ranks, toggles, Revised Art nor the server. Fix: one clickable assumptions line ("Lv100 · สเตตัส 128 · RA5 · ไม่มีพาสซีฟ · เป้า Carron"), "RA −12%" in the base line, ranks / toggles / RA / server saved in presets.
3. **The desc hides a passive's lines while its toggle is off (owner's decision 2026-10-28),** so the player must already know a passive matters before reading what it does. Option: show them greyed with "(ปิดอยู่)" and keep the reveal when one is switched on.
4. **The dependency strip has no heading or legend:** English tags (CD CAST DUR DMG INFO) next to Thai chip labels; condition and mode toggles borrow skill icons (`DEP_NOT_SKILL`) and look like owned skills, with the condition only in the hover title; the order is the internal skill id; ranks only cycle upward and the pips are not clickable; `DEP_EXCLUSIVE` switches others off silently. Fix: a caption, skills / gear / target conditions as three groups, Thai tags or tag tooltips, clickable pips, a toast when a toggle turns another off.
5. **The numbers players want come last and shrink to fit (owner's decision: no scrolling):** head, desc, strip and summon block come before CD / cast / duration, then damage; the fit scale has no floor and text shrinks to 9 px (the dials and strip names to 6 px). Option: a key-numbers line under the name, long descs collapsed after about 3 lines, a scale floor (about 0.85) with scrolling below it.
6. **No rank comparison:** the rank changes only by cycling the icon and its number exists only in the hover title. Fix: a visible "Lv 3/4" with − / +, a collapsible per-rank table, a lasting "+x vs Lv2" note on the chip.
7. **Trust notes are 22 px icons** (about 144 `tooltipNote`, 50 `bbBug`, 35+ `unintended`); the bug and unintended labels say "(BB)" even on the ToT / TTO tabs; `liveCheck` is on 2 cards; no card says where its numbers come from. Fix: a one-line banner when a note affects the numbers, naming its server; a short source footer.
8. **The animation delays values and miscolours them:** changed values stay frozen until the light lands (45 ms stagger per field, flights up to 620 ms, a 250 ms lead, a 520 ms roll, 800 ms after typing); changes are held while the Buff / server popups are open, so a buff's effect can't be watched while picking its level; "better" on damage chips uses ATK's red `#ef4444` while "worse" is `rgb(255,96,76)`. Fix: show the value at once and let the light decorate; keep the card live behind the popups; gold for every "better".
9. **Damage-row jargon:** ⌊ ⌋ ⌈ ⌉, "ค่าคงที่", nothing explains ดาเมจดิบ → ดาเมจจริง, no legend for the purple / aqua / gold numbers, an English "Knockout value" tooltip, an LCK spread tooltip with no heading.
10. **Internal names leak:** the card title "nAttack" on 10 classes; raw status keys in brackets where a status has no display name (`[damagePlus3]`; the owner's 2026-10-28 screenshot of the BB issues page shows `[holyWolf5]`, `[darkEdge]`, `[lunarEclipse]` the same way, Inferred to be the same cause); tooltips "damageMod / hitMod"; the custom buff form in English. Search ignores `nameTha` ("โจมตีปกติ" finds nothing) and results show no class (10 "Charge Attack", 10 "nAttack", 12 "Mount - Attack").
11. **Hidden interactions:** the target edit (owner's decision: no icon or hint), the rank cycle is the icon, the 3D preview is the range pill, the game tooltip is a gold H, Ctrl+wheel / Ctrl± are taken for tool zoom, and there is no shortcut sheet; the first search keystroke (the second, since the quick wins) wipes the open card; the same grid icon means "Common" and "browse by class".

## 6. Accessibility and phone

1. **Focus is lost on every rebuild:** the card, server tabs and strip are re-rendered through `innerHTML` (`renderBdPopup` the same), so after each toggle focus falls to `<body>`. Fix: remember a key for the focused control (`data-dep-id`, `data-role`, `data-server`, `data-key`) and refocus after the rebuild, or patch in place.
2. **Pop-ups are not real dialogs:** only the game-tip modal traps Tab and returns focus; the server pop-up and Buff / Debuff never take or return focus; the reach pop-up has no ×, and its toggles are `div role="button"` with click handlers only (Enter / Space do nothing); the enemy picker is a `listbox` holding a text input, without arrow keys or `aria-expanded`; the PRESET window has no Tab trap. Fix: one shared `openDialog(el, opener)` helper; real buttons and a visible × in the reach pop-up.
3. **Mouse or hover only:** the target edit is a click on a `div` (no tabindex, role or key handler); status keywords are `span onclick`; the odds tooltip is `:hover` only, so phones never see the odds; dep conditions live only in `title`. Fix: chips as buttons, status keywords as `button aria-expanded`, an ⓘ that opens the odds on tap or focus, the condition printed under `(hover:none)`.
4. **The stat dials have no accessible names** (17 `label` + `input` pairs without `for` / `id`, the same labels for player and enemy), and the grid's arrow keys block ↑ / ↓ stepping and caret moves inside a number. Fix: `aria-label="ATK ผู้เล่น"` / `"ATK เป้าหมาย"`; grid moves on Ctrl+arrows.
5. **The roster tabs** say `role="tab"` but ← / → switch the skill. Build the tab pattern or drop the role.
6. **Held values are hidden from screen readers** (`rollHold`: the new value `visibility:hidden`, the old copy `aria-hidden`); the tool has no `aria-live`; the one toast is created and filled in the same tick; Test results float for about 3 s as one `<img alt="1">` per digit. Fix: a visually hidden live copy of the new value, a toast region created at mount, a polite live region and a lasting last-result line per Test.
7. **Browser zoom is cancelled on desktop** (`fitStageToScreen`, no scale floor) and text shrinks to 6 px, so low-vision users can't enlarge anything (WCAG 1.4.4). Fix: the scrolling layout when the browser is zoomed, a fit floor of 1, a 10 px shrink floor.
8. **Touch gaps:** undo is Ctrl+Z only (and the toast tells phones to press it); the ‹ › skill buttons are hidden above 900 px (iPad landscape); the Buff switch is 28 × 16 px inside the Buff button, the enemy ⓘ 18 px, the reach badge 18 px tall, and only the 32 px icon of a strip item can be tapped; a plain tap closes the reach pop-up and phones still see "W A S D". Fix: an undo button in the toast, ‹ › on `(pointer:coarse)`, 44 px hit areas, the whole strip item one button, a × instead of tap-to-close.
9. **Motion (owner's decision 2026-10-13, enforced by `[MOTION ERROR]`):** comets on every click, the reach fly-in and endless orbit, `simGlow`. The reviewers' option that keeps the OS setting ignored: an in-app "ลดการเคลื่อนไหว" switch (values at once with a flash, no fly-in or auto-orbit); it needs the owner's OK and a validator exception. The CSS comment near `.view` claiming its entrance animation "still respects the preference" is false.
10. **Contrast and colour-only meaning:** faded stats (`opacity:.42`) measure 1.9-2.4:1 for labels and 2.9-3.4:1 for numbers on all four looks; red SP (spent) and blue SP (only required) differ by colour alone; better / worse is gold vs red while ▲ / ▼ follows the number; dep on / off is greyscale only; the soft LCK glow is opacity and ring tint only. Fix: fade the ring, not the text; label the SP pills; add a non-colour "on" mark.
