# Status Effect Glossary Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new Bible hub tool, สารานุกรมสถานะ (`#status-glossary`), listing every status of every server with its type, effect per level, formula and sources (skills, gear, pets).

**Architecture:** All code and data live in `12t_projects/bible/index.html` (patched out-of-process, CRLF), icons in a new `assets.js` container `STATUS_ICONS`. The list comes from an embedded copy of the games' status tables; text comes from the existing `STATUS_CLASS_MAP` / `STATUS_DESC_MAP` / `STATUS_DESC_SERVER` through `getStatusDesc`; skill sources are derived at first open from `SKILLS` with a Thai-context classifier plus a correction table. Checks go into `scripts/validate_skills.js` as `[STATUS GLOSSARY ERROR]`.

**Tech Stack:** Vanilla JS / CSS inside the single-file hub; Node validator (vm sandbox); Python 3.10 + Real-ESRGAN for icons.

**Spec:** [docs/superpowers/specs/2026-11-16-status-glossary-design.md](../specs/2026-11-16-status-glossary-design.md)

## Global Constraints

- `index.html` is edited only by Node scripts in the session scratchpad that back the file up first, normalise anchors to `\r\n`, check match counts, and print one line (12t_projects/bible/CLAUDE.md §1). Never `git checkout` / `restore` / `reset` / `stash` it.
- Icons go to `assets.js` via a scratch script, then `node scripts/bible_assets.js stamp`; `STATUS_ICONS` is added to `MANIFEST` in `scripts/bible_assets.js`.
- Fonts: Prompt for text, `'JetBrains Mono','Prompt',monospace` for numbers. No reduced-motion gates. Hover = small lift / brightness, never a gold glow.
- New panels use colour tokens and join `THEME_SURFACES` (panel / raised / popup / field). New colours need dark values only.
- No value without a code citation (AGENTS.md §4). Research findings go to the reference docs before the page.
- Player text is Thai in the house style (bible-desc-writing); commit subjects and changelog entries in Thai; product names stay English.
- Storage key `12t-bible-status`; every storage access in try / catch.
- Validator: `node scripts/validate_skills.js` must end with 0 errors after each task.

## Review Focus

1. A status key that exists in two spellings (`atkUp` / `atkup` in `STATUS_CLASS_MAP`): one tile, not two. → Task 1 test "one tile per lower-cased key".
2. A server-only status opened by deep link on another server (`#status-glossary/gilded?server=og`): falls back to the status's own server rather than an empty panel. → Task 5 test.
3. A description entry that throws or returns nothing at some level (functions written for `sLv` 1-5 opened at level 9): the panel shows the formula line and no raw markup / `NaN`. → Task 5 test over every status × level 1..max × server.
4. Stored state from an older version or garbage (`{"server":"xx","key":"nope","lv":-3}`): opens on defaults. → Task 5 test.
5. A card edited later to mention a new status: the validator names the unclassified pair instead of the glossary silently listing a mention as a source. → Task 3 test.
